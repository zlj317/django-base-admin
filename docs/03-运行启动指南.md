## 3. 数据库准备

### 3.1 创建数据库

```sql
CREATE DATABASE gen_admin DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

### 3.2 执行建表 SQL（推荐方式 A）

用 MySQL 客户端导入 `docs/后台管理系统-初始化建表SQL.sql`：

```bash
mysql -u root -p gen_admin < docs/后台管理系统-初始化建表SQL.sql
```

该脚本会创建以下表：

- 系统表：`sys_user`、`sys_role`、`sys_menu`、`sys_dept`、`sys_user_role`、`sys_role_menu`、`sys_dict_type`、`sys_dict_data`、`sys_config`、`sys_oper_log`、`sys_login_log`、`sys_gen_table`、`sys_gen_table_column`
- 示例业务表：`biz_student`

**附加模块（可选但推荐）**：如需启用附件管理、消息中心、公告通知、定时任务、报表管理、报表大屏、外部对接 7 个附加模块，再导入一次 `docs/additional_module_init.sql`：

```bash
mysql -u root -p gen_admin < docs/additional_module_init.sql
```

该脚本会创建 22 张扩展表并写入附件管理的 8 条默认配置（存储方式、kkFileView/OnlyOffice 服务地址、白名单、水印开关、清理周期等）。

### 3.3 初始化数据（方式 B，推荐与方式 A 配合）

后端提供了自定义命令：

```bash
cd backend
python manage.py init_db
```

它会：创建 `gen_admin` 库（若不存在）→ 执行主系统 SQL → **自动执行 `additional_module_init.sql`**（附加模块 22 张表）→ 将 admin 密码重置为 `123456` → 初始化菜单与按钮权限并授权超级管理员（包含 7 个顶级附加菜单与全部二级页面菜单）。

> **重要**：`backend/core/management/commands/init_db.py` 中的 `SQL_FILE` 与 `ADDITIONAL_SQL_FILE` 是写死的 Windows 路径。在 Linux/macOS 或换了目录后，先修改这两个常量为实际绝对路径，再执行命令。

> 附加模块详情见 [03-附加模块清单.md](./03-附加模块清单.md) 与 [django-base-admin附加模块需求说明书.md](./django-base-admin附加模块需求说明书.md)。

## 4. 后端配置

编辑 `backend/config/settings.py`：

| 配置项 | 说明 | 本地示例 |
|---|---|---|
| `DATABASES` | MySQL 连接（host/port/user/password/name） | `127.0.0.1:3306`、`root`、`gen_admin` |
| `SECRET_KEY` | JWT 签名密钥 | 生产必须更换为随机值 |
| `DEBUG` | 调试模式 | 本地 `True`，生产 `False` |
| `ALLOWED_HOSTS` | 允许访问的域名 | 本地 `['*']` 或 `127.0.0.1` |
| `CORS_ALLOW_ALL_ORIGINS` | 跨域 | 本地 `True`，生产改为白名单 |
| `TIME_ZONE` | 时区 | `Asia/Shanghai` |

> JWT 参数在 `JWT_CONFIG` 中（有效期 2 小时、续期阈值 30 分钟等）。

## 5. 启动后端

```bash
cd backend

# 1) 创建虚拟环境（仅首次）
python -m venv venv

# 2) 激活虚拟环境
# Windows PowerShell:
.\venv\Scripts\Activate.ps1
# Windows CMD:
# .\venv\Scripts\activate.bat
# macOS / Linux:
# source venv/bin/activate

# 3) 安装依赖
pip install -r requirements.txt

# 4) 语法与配置检查（可选）
python manage.py check

# 5) 启动
python manage.py runserver 0.0.0.0:8000
```

说明：

- 本项目**不使用 migrations**：所有模型 `managed=False`，表由 SQL 创建，**不要执行** `makemigrations/migrate`。
- 开发时如需热重载可去掉 `--noreload`；后台运行或调试代码改动时使用 `--noreload` 更可控（改代码后需手动重启）。
- 启动成功后访问 `http://127.0.0.1:8000/api/auth/login` 应返回 JSON（GET 会提示方法不允许，说明服务已通）。

## 6. 启动前端

```bash
cd frontend

# 1) 安装依赖
npm install

# 2) 开发模式（默认 5173，/api 自动代理到 127.0.0.1:8000）
npm run dev

# 3) 生产构建（产物在 dist/）
npm run build

# 4) 本地预览构建产物
npm run preview
```

`vite.config.js` 中已配置：

```js
server: {
  port: 5173,
  proxy: { '/api': { target: 'http://127.0.0.1:8000', changeOrigin: true } }
}
```

浏览器打开 `http://localhost:5173`，使用 `admin / 123456` 登录。

## 7. 验证清单

### 7.1 页面验证

1. 登录页正常显示 → 登录成功进入 Dashboard；
2. 左侧菜单显示：首页、系统管理（8 个子菜单）、系统工具（代码生成）、学生信息表、**附件管理、消息中心、公告通知、定时任务、报表管理、报表大屏、外部对接**（7 个附加顶级菜单，各含 2~4 个二级页面）；
3. 用户管理列表有 admin/zhangsan；admin 状态为「正常」且自身开关禁用；
4. 打开「代码生成」，表列表出现已导入的 `biz_student`；
5. 打开「学生信息表」，CRUD/导入/导出可用；
6. 打开「附件管理 → 上传配置」，可见 8 条默认配置（存储方式 local、kkFileView 地址 `http://127.0.0.1:8012`、OnlyOffice 地址 `http://127.0.0.1:8080` 等）；
7. 打开「定时任务 → 任务日志」，应能正常查询（首次为空）。

### 7.2 接口验证

PowerShell：

```powershell
$body = @{username='admin';password='123456'} | ConvertTo-Json
$r = Invoke-RestMethod -Uri 'http://127.0.0.1:8000/api/auth/login' `
  -Method Post -ContentType 'application/json' -Body $body
$h = @{ Authorization = "Bearer $($r.data.token)" }
Invoke-RestMethod -Uri 'http://127.0.0.1:8000/api/system/user/list?page=1&page_size=10' -Headers $h
```

curl：

```bash
TOKEN=$(curl -s -X POST http://127.0.0.1:8000/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"123456"}' | jq -r '.data.token')

curl -s http://127.0.0.1:8000/api/system/user/list?page=1&page_size=10 \
  -H "Authorization: Bearer $TOKEN"
```

注意：

- 路径**不带尾斜杠**（带斜杠会 301，PUT 可能失败）；
- 必须带 `Authorization: Bearer <token>`；
- 业务结果看响应体 `code`（HTTP 恒 200）。

## 9. 常见问题（FAQ）

| 现象 | 原因 | 处理 |
|---|---|---|
| `Can't connect to MySQL server` | 数据库未启动/地址端口错误 | 检查 MySQL 服务与 `DATABASES`；确认库 `gen_admin` 存在 |
| 登录返回「用户名或密码错误」 | 未执行初始化或密码错误 | 执行 `python manage.py init_db`；确认 admin/123456 |
| 页面接口 401 | token 过期/未登录/用户停用 | 重新登录；检查用户状态；确认请求头 Bearer |
| 页面接口 403 | 角色无对应权限 | 角色管理分配菜单/按钮权限；确认 `perm_map` 标识 |
| 代码生成接口 404 | 前端路径缺少 `/gen` 前缀或多尾斜杠 | 使用 `/api/gen/table/list` 等无尾斜杠路径 |
| `/api/api/...` 双重前缀 | 业务路径又写了 `/api` | `request` 的 baseURL 已是 `/api`，业务路径去掉 `/api` |
| 前端 404 页面（深层链接） | 动态路由未注册/守卫问题 | 登录后刷新；检查 `router/index.js` 守卫按 `path` 重新解析 |
| `init_db` 找不到 SQL | `SQL_FILE` 为写死的 Windows 路径 | 修改该常量为实际路径后重试 |
| 前端启动报端口占用 | 5173 已被占用 | 关闭旧进程或修改 `vite.config.js` 的 port |
| 修改后端代码不生效 | 使用了 `--noreload` | 手动重启后端 |
| 生成表字段为空/类型异常 | 模型与表结构不一致 | 核对 SQL 表字段与生成的 `models.py` |
| 导出中文乱码（Excel） | 未使用二进制响应/编码问题 | 确认导出接口使用 `openpyxl` 生成 xlsx 并以 blob 下载 |
