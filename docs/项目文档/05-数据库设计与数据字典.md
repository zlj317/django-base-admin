## 1. 设计约定

| 约定 | 说明 |
|---|---|
| 数据库 | MySQL 8.x，`utf8mb4` / `utf8mb4_general_ci` |
| 主键 | `BIGINT`，雪花算法生成，不使用自增（3D 模块在注释中明确要求） |
| 逻辑删除 | `is_deleted TINYINT DEFAULT 0`，查询默认过滤 `is_deleted=0` |
| 审计字段 | `create_by` / `create_time` / `update_by` / `update_time` |
| 状态字段 | 常见 `status TINYINT DEFAULT 1`（1 启用 / 0 禁用）；基础平台沿用 `0 正常 / 1 停用`，以字段注释为准 |
| 建表方式 | `python manage.py init_db` 顺序执行 `docs/*.sql`，脚本幂等（`CREATE TABLE IF NOT EXISTS`） |

> ORM 模型通过 `Meta.db_table` 映射到下列物理表，未使用 Django 自动建表；`sys_user_role`、`sys_role_menu` 等多对多中间表为纯 SQL 表。

### 1.2 索引与约束策略

- 业务唯一键使用 `UNIQUE KEY`（如 `uk_username`、`uk_category_code`、`uk_template_code`），避免重复编码。
- 关联字段统一建普通索引（`idx_*_id`），状态与逻辑删除字段建 `idx_status` / `idx_is_deleted`，兼顾列表过滤性能。
- 关联关系以应用层校验 + 索引为主，脚本未声明物理外键（`SET FOREIGN_KEY_CHECKS = 0`），便于分库与数据迁移。
