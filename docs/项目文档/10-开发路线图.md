## 2. 当前状态评估

### 2.1 优势

- 业务覆盖面完整：24 个应用、93 张表（实际库）、24 个路由前缀；
- 工程约定统一：统一响应、雪花 ID、逻辑删除、操作日志、权限标识；
- 3D 模块闭环：场景 → 对象 → 绑定 → 告警 → 巡检 → 发布 → 分享；
- 前端主题体系成熟：令牌化、明暗 + 5 色、无硬编码；
- 文档体系完整：功能、启动、中间件、接口、数据库、测试、运维、FAQ、术语、路线图。

### 2.2 短板

| 短板 | 影响 | 优先级 |
|---|---|---|
| 无自动化测试与 CI | 回归依赖人工脚本，重构风险高 | P0 |
| 调度/推送/备份/预览/存储为演示级 | 不能直接用于生产 | P0/P1 |
| 文件预览地址硬编码 | 换环境必须改代码 | P1 |
| `init_db` SQL 绝对路径 | 换机器需改代码 | P1 |
| 无真实监控采集 | 告警记录依赖外部写入 | P1 |
| 移动端未专项适配 | 小屏体验未验证 | P2 |
| 无 API 文档自动化（Swagger） | 接口变更需手工同步 | P2 |

## 3. 后续规划

### 3.1 M11 工程化与质量（P0）

| 任务 | 说明 | 验收 |
|---|---|---|
| 接口自动化测试 | 用 `pytest + requests` 固化 250 项回归 | 一条命令跑完并输出报告 |
| CI 流水线 | 后端 `manage.py check` + 前端 `npm run build` + 回归 | PR 必过 |
| 配置外置 | SQL 路径、数据库账号、`SECRET_KEY` 改环境变量 | 换机器零改代码 |
| 统一异常与日志 | 日志轮转、request_id 贯穿 | 可按 trace 排查 |

### 3.2 M12 真实基础设施（P0/P1）

| 任务 | 说明 | 验收 |
|---|---|---|
| Celery + Redis | 定时任务真实调度、消息异步发送 | CRON 到点自动执行并写日志 |
| 备份服务 | 调用 `mysqldump`、落盘/上传、保留策略 | 可下载真实备份文件 |
| 对象存储 | 接入 MinIO，替换本地磁盘 | `storage_type=minio` 生效 |
| 预览服务 | kkFileView / OnlyOffice 地址读配置，不写死 | 换地址仅改配置 |
| 监控采集 | CPU/内存/磁盘/接口耗时定时采集并触发告警 | 告警自动产生 |

### 3.3 M13 权限与安全增强（P1）

| 任务 | 说明 |
|---|---|
| 数据权限落地 | 在 CrudViewSet 查询层统一注入行级过滤 |
| 脱敏落地 | 序列化输出阶段统一按角色掩码 |
| 安全策略落地 | IP 黑白名单与限流在网关层生效并留痕 |
| 多租户隔离 | 查询自动追加 `tenant_id`，并补端到端用例 |
| 操作日志归档 | 按月分表/归档，提供导出 |

### 3.4 M14 3D 与可视化增强（P1/P2）

| 任务 | 说明 |
|---|---|
| 模型格式扩展 | GLTF/GLB 校验与缩略图生成 |
| 场景协同 | 多人编辑锁与冲突提示（需 WebSocket） |
| 实时数据推送 | 数据绑定读数通过 SSE/WebSocket 实时刷新 |
| 巡检自动化 | 按路线定时生成记录并联动告警 |
| 大屏模板 | 预置机房/产线模板，一键套用 |

### 3.5 M15 体验与文档（P2）

| 任务 | 说明 |
|---|---|
| 移动端适配 | 1280 以下断点、表格横向滚动、手势 |
| 无障碍与国际化 | 键盘操作、对比度、i18n 文案抽取 |
| OpenAPI | DRF Spectacular 自动生成 Swagger，与 04 文档双向核对 |
| 文档站点 | 将 docs 构建为静态站点，支持全文检索 |

## 4. 技术债清单
