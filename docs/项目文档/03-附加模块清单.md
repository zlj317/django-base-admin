## 2. 菜单树结构（7 顶级 M → 18 二级 C = 25 个页面）

菜单由 `init_db` 的 seed 逻辑写入 `sys_menu`，`menu_type` 为 M（目录）或 C（页面）。

```
附件管理（M, /file）
  ├ 附件列表（C, /file/index）
  ├ 上传配置（C, /file/config）
  ├ 预览配置（C, /file/preview）
  └ 附件回收站（C, /file/recycle）
消息中心（M, /msg）
  ├ 消息模板（C, /msg/template）
  ├ 站内消息（C, /msg/record）
  ├ 消息推送记录（C, /msg/push_log）
  └ 推送配置（C, /msg/push_config）
公告通知（M, /notice）
  ├ 公告列表（C, /notice/index）
  └ 公告分类（C, /notice/category）
定时任务（M, /task）
  ├ 任务列表（C, /task/index）
  └ 任务日志（C, /task/log）
报表管理（M, /rp）
  ├ 报表设计（C, /rp/template）
  ├ 报表生成（C, /rp/generate）
  ├ 报表查询（C, /rp/query）
  └ 报表实时查询（C, /rp/realtime）
报表大屏（M, /bi）
  ├ 大屏设计（C, /bi/design）
  ├ 大屏管理（C, /bi/index）
  └ 大屏访问记录（C, /bi/visit_log）
外部对接（M, /outer）
  ├ 接口配置（C, /outer/api_config）
  ├ 请求日志（C, /outer/request_log）
  └ 数据同步任务（C, /outer/sync_task）
```

合计：7 个顶级菜单 + 18 个页面菜单 = **25 个 C/M**，加上按钮权限（`F` 类型）每个页面至少 3~5 个，全部由 seed 写入。

## 5. 跨模块依赖速查

```
定时任务 (task_sched)
  ├── 过期附件清理 ──→ 附件管理 (file)
  ├── BPMN 超时检测 ──→ 工作流审批 (workflow)
  ├── 报表定时生成 ──→ 报表管理 (report) ──→ 附件管理 (file) + 外部对接 (outer)
  └── 消息推送重试 ──→ 消息中心 (msg)

公告通知 (notice) ──发布──→ 消息中心 (msg)
报表大屏 (bi) ──数据源──→ 外部对接 (outer)
报表大屏 (bi) ──快照──→ 附件管理 (file)
外部对接 (outer) ──同步任务──→ 定时任务 (task_sched)
```

## 6. 初始化 checklist

首次部署附加模块时按以下顺序执行：

1. `python manage.py init_db`（自动建 22 张表 + 写入 8 条附件默认配置 + seed 7 顶级菜单与 18 页面菜单）
2. 启动后端、启动前端，登录 admin/123456
3. 检查侧边栏出现 7 个顶级菜单
4. 打开「附件管理 → 上传配置」确认 8 条默认配置已写入
5. 如需 MinIO：修改 `wf_file_config` 中 `file.storage.type=minio` 并补充 bucket 配置
6. 如需 kkFileView / OnlyOffice：分别部署对应服务并在配置中更新地址
7. 如需 Celery：启动 Redis 与 Celery Worker，定时任务模块的启停按钮才会真正调度
