## 1. Django 中间件

真实配置（`backend/config/settings.py`）：

```python
MIDDLEWARE = [
    'corsheaders.middleware.CorsMiddleware',
    'django.middleware.common.CommonMiddleware',
    'common.middleware.OperLogMiddleware',
    'common.middleware.TokenRefreshMiddleware',
]
```

| 中间件 | 作用 | 关键行为 | 注意事项 |
|---|---|---|---|
| `CorsMiddleware` | 跨域 | `CORS_ALLOW_ALL_ORIGINS=True`、`CORS_ALLOW_HEADERS=('*',)` | 生产应改为域名白名单 |
| `CommonMiddleware` | 请求规范化 | 补全/校验结尾斜杠、`APPEND_SLASH` 默认行为 | 前端请求统一带尾斜杠可避免 301 |
| `OperLogMiddleware` | 操作日志 | 仅记录 `/api/` 下 POST/PUT/DELETE；请求/响应体各截断 2000 字节；跳过登录/登出 | 写库失败只记 logger，不影响业务响应 |
| `TokenRefreshMiddleware` | Token 静默续期 | 剩余有效期 < 30 分钟且 > 0 时，响应头下发 `X-Refresh-Token` | 前端拦截器读取后替换本地 token |

### 1.1 操作日志推断规则

`OperLogMiddleware.OPER_TYPE_MAP` 按 URL 关键字推断操作类型：

| URL 关键字 | 操作类型 |
|---|---|
| `importTemplate` / `importData` / `import` | 导入 |
| `export` | 导出 |
| `create` | 新增 |
| `update` / `assign` / `reset_pwd` / `status` | 编辑 |
| `delete` | 删除 |
| 其它 | 其他 |

写入字段：`oper_user`、`module_name`、`oper_type`、`request_url`、`request_param`、`response_result`、`cost_time`、`oper_time`。

### 1.2 JWT 认证（非 Django 中间件，属于 DRF 认证类）

| 配置项 | 值 | 说明 |
|---|---|---|
| `JWT_CONFIG['ALGORITHM']` | `HS256` | 对称签名 |
| `JWT_CONFIG['EXPIRE']` | 2 小时 | 登录有效期 |
| `JWT_CONFIG['REFRESH_THRESHOLD']` | 30 分钟 | 静默续期阈值 |
| `SECRET` | 复用 `SECRET_KEY` | 生产必须替换 |

认证类 `common.auth.JWTAuthentication` 解析 `Authorization: Bearer <token>`，把用户挂到 `request.user_info`，权限判定再读取 `request.jwt_payload`。

## 2. 中间件执行顺序与数据链路

```
请求 → CORS → CommonMiddleware → OperLog（进入前读 body）
     → TokenRefresh（进入前透传）→ DRF 认证 → PermissionCheck → ViewSet → ORM
响应 ← CORS ← CommonMiddleware ← OperLog（写 sys_oper_log）
     ← TokenRefresh（必要时写 X-Refresh-Token）← 统一响应 {code,msg,data}
```

- 越靠前越外层：CORS 必须最外层，保证 4xx/5xx 也带跨域头；
- OperLog 在业务前读取 `request.body` 并缓存，DRF 后续仍可正常解析；
- TokenRefresh 在业务后读取 `request.jwt_payload`，未认证请求自动跳过。

## 3. MySQL 安装与配置

### 3.1 安装

| 平台 | 命令/安装包 |
|---|---|
| Windows | MySQL 8.0 Installer（勾选 MySQL Server + 命令行工具） |
| CentOS / Ubuntu | `yum install mysql-server` / `apt install mysql-server` |
| Docker | `docker run -d --name mysql8 -p 3306:3306 -e MYSQL_ROOT_PASSWORD=root mysql:8.0` |

### 3.2 建库

```sql
CREATE DATABASE IF NOT EXISTS gen_admin
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
```

### 3.3 Django 连接

```python
DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.mysql',
        'NAME': 'gen_admin',
        'USER': 'root',
        'PASSWORD': 'root',
        'HOST': '192.168.0.76',
        'PORT': '3306',
        'OPTIONS': {'charset': 'utf8mb4'},
    }
}
```

- 驱动：`pymysql.install_as_MySQLdb()`（`backend/config/__init__.py`），Windows 无需编译 mysqlclient；
- `USE_TZ=False`，手工 SQL 使用 `NOW()` 写入本地时间；
- 生产建议：独立账号、最小权限、`max_connections` 按并发调整、开启慢查询日志。

### 3.4 表结构安装

```bash
mysql -u root -p gen_admin < docs/additional_module_init.sql
cd backend && python manage.py init_db
```

`init_db` 负责其余 4 个脚本与全部种子数据，详见 [启动运行指南 4.2](./02-项目启动运行指南.md#42-执行-init_db)。

## 4. 附件存储与预览服务

### 4.1 内置配置（`wf_file_config`）

| 配置键 | 默认值 | 含义 |
|---|---|---|
| `file.upload.max_size` | `10` | 单文件上限（MB） |
| `file.upload.chunk_size` | `5` | 分片大小（MB） |
| `file.upload.whitelist` | `jpg,png,gif,pdf,doc,docx,xls,xlsx,ppt,pptx,txt,zip,mp4,mp3` | 后缀白名单 |
| `file.storage.type` | `local` | `local` 本地磁盘 / `minio` 对象存储（配置项预留） |
| `file.preview.kkfileview_url` | `http://127.0.0.1:8012` | kkFileView 服务地址 |
| `file.preview.onlyoffice_url` | `http://127.0.0.1:8080` | OnlyOffice 服务地址 |
| `file.watermark.enable` | `0` | 预览水印开关 |
| `file.expire.clean_days` | `30` | 过期附件清理周期（天） |

### 4.2 实际存储行为

- 上传文件保存到后端 `uploads/YYYYMM/` 目录，文件名使用 `uuid + 原扩展名`；
- 按文件 MD5 去重，重复文件秒传并写附件记录；
- 逻辑删除进回收站，可恢复或彻底删除（彻底删除会移除磁盘文件）；
- 代码中**未接入 MinIO SDK**，`storage_type=minio` 目前仅作为配置项保留，实际仍落本地磁盘；
- 下载接口：`GET /api/file/download/<pk>`，以 `original_name` 作为下载文件名。

### 4.3 kkFileView（可选安装）

```bash
docker run -d --name kkfileview -p 8012:8012 keking/kkfileview:4.4.0
```

- 访问 `http://localhost:8012` 确认页面可打开；
- 后端 `preview_url` 使用固定地址 `http://localhost:8012/onlinePreview?url=...`，**未读取** `wf_file_config` 中的地址；若部署在其他主机，需要修改 `backend/apps/file/views.py` 的 `kk_url`（属代码改动，非配置）；
- kkFileView 需要能访问到对应文件的 URL，生产环境应把 `/uploads` 暴露为可访问静态路径。

### 4.4 OnlyOffice（可选安装，当前为占位）

```bash
docker run -d --name onlyoffice -p 8080:80 onlyoffice/documentserver
```

- 后端 `office_url` 返回 `/onlyoffice/editor?fileId=...`，仓库内**没有对应的编辑器页面与文档服务回调**，属占位地址；
- 若需真正集成，需要同时补齐前端编辑器页、JWT 回调与文件保存接口。

### 4.5 对象存储（预留）

`file.storage.type` 已预留 `minio` 选项，但依赖中没有 MinIO SDK。接入步骤（规划）：

1. `pip install minio` 并配置 endpoint / bucket / access key；
2. 在文件上传、下载、删除三处替换本地磁盘操作；
3. 迁移历史文件并保留 `storage_path` 兼容。

## 5. Nginx 反向代理

生产推荐拓扑：Nginx 托管前端静态资源，`/api/` 反代后端。

```nginx
server {
    listen 80;
    server_name admin.example.com;

    # 前端静态资源（npm run build 产物）
    location / {
        root /opt/app/frontend/dist;
        try_files $uri $uri/ /index.html;   # 支持前端 History 路由
    }

    # 后端接口
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 60s;
    }

    # 附件静态访问（供 kkFileView 拉取）
    location /uploads/ {
        alias /opt/app/uploads/;
        expires 7d;
    }

    client_max_body_size 100m;              # 与上传上限匹配
}
```

> 后端可直接使用 `python manage.py runserver`（仅开发）或 Gunicorn / Waitress（生产）。仓库未提供 systemd 单元文件，可参考 [多平台部署指南](./04-多平台部署指南.md) 与 [运维手册](./07-运维手册.md)。

## 6. 预留中间件（Redis/Celery 等）

当前 `backend/requirements.txt` **不包含** Redis、Celery、Channels、MinIO、boto3。以下能力为预留/演示级：

| 能力 | 现状 | 若需启用 |
|---|---|---|
| 定时调度 | 任务配置与日志真实，手动触发写「演示」日志 | 引入 Celery + Redis，新增 beat 调度与 worker |
| 消息推送 | 站内消息真实，短信/邮件/Webhook 仅渠道配置 | 接入各渠道 SDK，在发送处替换占位 |
| 外部接口同步 | 配置/日志真实，`run_once` 为占位 | 用 `requests` 按配置发起真实调用 |
| WebSocket 实时 | 未引入 Channels | 增加 ASGI + Channels + Redis channel layer |
| 对象存储 | `storage_type` 配置预留 | 接入 MinIO SDK |
| 数据备份 | 手动备份写入模拟成功记录 | 调用 `mysqldump` 并落盘/上传 |

> 这些预留项不影响平台、工作流、附件、3D、首页等核心功能。补齐计划见 [开发路线图](./10-开发路线图.md)。
