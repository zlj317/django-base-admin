## 1. 启动与环境

### Q1：`python manage.py runserver` 报数据库连接失败？

检查 `backend/config/settings.py` 的 `HOST/PORT/USER/PASSWORD`，确认 MySQL 已启动、网络可达：

```bash
mysql -h 192.168.0.76 -u root -p -e "select 1"
```

本机开发可把 `HOST` 改为 `127.0.0.1`。

### Q2：Windows 下安装 `mysqlclient` 失败？

项目已使用 PyMySQL（`backend/config/__init__.py` 中 `pymysql.install_as_MySQLdb()`），无需编译 mysqlclient。确认已 `pip install PyMySQL`。

### Q3：端口被占用？

```powershell
netstat -ano | findstr :8000
```

结束占用进程，或改用其它端口并在 `vite.config.js` 的 proxy 中同步修改。

### Q4：前端启动后 `/api` 请求 404/502？

- 确认后端已启动在 `127.0.0.1:8000`；
- 检查 `frontend/vite.config.js` 的 proxy 配置；
- 不要直接用浏览器打开 `dist/index.html`（History 路由与接口代理都会失效），应通过 Nginx 或开发服务器访问。

## 2. 数据库与初始化

### Q5：`init_db` 报 `FileNotFoundError`？

`backend/core/management/commands/init_db.py` 中的 SQL 路径是 Windows 绝对路径（`d:\other\django-base-admin\docs\...`）。换目录/换机器后改成实际路径。

### Q6：`init_db` 报某张表不存在？

`init_db` 只执行 4 个 SQL，**不包含** `docs/additional_module_init.sql`。首次初始化必须先执行：

```bash
mysql -u root -p gen_admin < docs/additional_module_init.sql
```

再执行 `python manage.py init_db`。

### Q7：为什么不能 `makemigrations/migrate`？

本项目 SQL-first：模型全部 `managed=False`，表由 `docs/*.sql` 维护。执行 migrate 不会建业务表，反而可能产生额外表。新增/修改表结构请改 SQL 并同步模型。

### Q8：表数量对不上？

5 个脚本合计 92 张：基础 13 + 工作流 11 + 附加 22 + 增强 33 + 3D 13。可在库中核对：

```sql
SELECT table_name FROM information_schema.tables WHERE table_schema='gen_admin';
```

### Q9：初始化后菜单缺失？

- 确认 `init_db` 完整执行无异常；
- 重新执行：`python manage.py init_db --force-menus`；
- 检查 `sys_role_menu` 是否给 `admin` 角色授权（超管通过 `*:*:*` 通配，但仍需菜单存在）。

## 3. 登录与权限

### Q10：登录返回「用户名或密码错误」？

- 默认账号 `admin / 123456`；
- 若改过密码，可在数据库中重置或重新执行 `init_db`（会重置 admin 密码）；
- 确认 `sys_user.status=0`（正常）。

### Q11：登录后提示 401？

- Token 有效期 2 小时，过期需重新登录；
- 前端拦截器应在收到 `X-Refresh-Token` 时替换本地 token；
- 检查请求头是否为 `Authorization: Bearer <token>`。

### Q12：页面能进但按钮点击 403？

后端返回 `没有操作权限：xxx`。到「角色管理 → 菜单授权」勾选对应按钮权限；`admin` 角色拥有 `*:*:*`，不会出现该问题。

### Q13：菜单看不到？

菜单按角色下发，且 `menu_type=M/C` 才显示；`visible=1` 的隐藏菜单（如 3D 编辑器）不会出现在侧边栏。确认角色已授权、菜单状态启用。

## 4. 功能使用

### Q14：附件预览打不开？

后端 `preview_url` 返回 kkFileView 地址，固定为 `http://localhost:8012`。需要本机启动 kkFileView：

```bash
docker run -d --name kkfileview -p 8012:8012 keking/kkfileview:4.4.0
```

若部署在其它主机，需要修改 `backend/apps/file/views.py` 中的 `kk_url`（属代码改动）。

### Q15：OnlyOffice 预览无效？

`office_url` 返回 `/onlyoffice/editor?...` 占位地址，仓库内没有对应编辑器页面与回调，属预留能力。

### Q16：定时任务到点没有执行？

当前无 Celery/Redis，`run_once` 只写「手动触发（演示：未实际调度）」日志。需要真实调度请按 [开发路线图](./10-开发路线图.md) 接入。

### Q17：消息发不出去 / 收不到短信？

站内消息真实落库；短信/邮件/Webhook 仅有渠道配置，未接真实网关。

### Q18：报表「生成」没有文件？

`POST /api/rp/template/generate/<pk>` 返回图表渲染数据并写生成记录，不产出 Excel/PDF。

### Q19：数据备份没有文件？

`POST /api/backup/record/manual` 只写模拟成功记录。真实备份请用 `mysqldump`（见 [运维手册](./07-运维手册.md#41-数据库备份真实可执行)）。

### Q20：大屏分享链接打不开？

- `POST /api/bi/screen/publish/<pk>` 后才会生成可访问的分享地址；
- BI 分享接口仍需登录态；3D 分享接口才是免登录。

### Q21：首页某些卡片显示「暂无数据」？

这是设计内的引导态：对应模块没有真实数据时不使用 mock，展示用途说明与跳转入口。写入数据后刷新即可显示。

## 5. 前端与主题

### Q22：切换主题后部分区域颜色没变？

页面不应写死颜色，须使用 `--app-*` / `--brand-*` 令牌。若是新页面，检查是否用了硬编码色值。

### Q23：刷新后主题恢复默认？

主题存于 `localStorage["app-theme"]`。检查浏览器是否禁用本地存储、是否清理过站点数据。

### Q24：`npm run build` 失败？

- 确认 Node 18+；
- 删除 `node_modules` 与 `package-lock.json` 后重新 `npm install`；
- 检查是否有未使用的导入/语法错误（Vite 会直接报错）。

### Q25：页面刷新 404？

前端为 History 模式，Nginx 必须配置：

```nginx
try_files $uri $uri/ /index.html;
```

## 6. 3D 模块

### Q26：3D 页面空白/一直加载？

- 查看 Network 中 three chunk 是否加载成功；
- 确认模型资源地址可访问；
- 浏览器需支持 WebGL，可打开 `chrome://gpu` 检查。

### Q27：发布场景失败？

- 场景必须至少 1 个对象；
- 对象引用的模型资源必须存在且启用；
- 未发布场景不能生成分享链接。

### Q28：分享页 404？

- 场景必须已发布；
- token 有效期 1~30 天，过期需重新生成；
- 分享接口 `GET /api/scene3d/share/<token>` 免登录，但前端路由 `/scene3d/share/:token` 需要正确的 token。

### Q29：模型上传失败？

- 检查后缀白名单（模型/贴图格式）与 50MB 限制；
- 检查 `uploads/` 目录写权限。

### Q30：告警记录不产生？

告警规则与记录表真实，但当前没有后台采集进程；需要外部写入或接入监控采集。3D 数据绑定的预览读数用于演示阈值配色。

## 7. 部署与运维

### Q31：生产环境需要哪些服务？

必需：MySQL、后端（Gunicorn/Waitress）、Nginx。可选：kkFileView。Redis/Celery/MinIO/OnlyOffice 当前未内置。

### Q32：如何修改上传大小限制？

同时修改：`wf_file_config` 的 `file.upload.max_size`、Nginx `client_max_body_size`、后端接收限制（如有）。

### Q33：如何清理历史日志？

使用页面「清空」按钮，或按时间删除：

```sql
DELETE FROM sys_oper_log WHERE oper_time < DATE_SUB(NOW(), INTERVAL 6 MONTH);
```

### Q34：升级后如何回滚？

代码回滚 + 重新构建前端；如涉及表结构变更，需用数据库备份恢复到变更前，详见 [运维手册 5.3](./07-运维手册.md#53-回滚)。
