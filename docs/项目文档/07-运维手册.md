## 2. 日常巡检

### 2.1 每日检查

| # | 项目 | 命令/方式 | 正常标准 |
|---|---|---|---|
| 1 | 后端存活 | `curl -s http://127.0.0.1:8000/api/home/overview/ -o /dev/null -w "%{http_code}"` | 200 |
| 2 | 登录可用 | `POST /api/auth/login`（admin） | `code=200` |
| 3 | 数据库连接 | `mysql -e "select 1"` | 返回 1 |
| 4 | 表数量 | `select count(*) from information_schema.tables where table_schema='gen_admin'` | ≥ 92 |
| 5 | 磁盘 | `df -h` / Windows 资源管理器 | 使用率 < 80% |
| 6 | 附件目录增长 | `du -sh uploads/` | 与业务量匹配 |
| 7 | 错误日志 | 检查后端 stderr / Nginx error.log | 无持续 5xx |
| 8 | 操作日志 | 抽查 `sys_oper_log` 最新记录 | 有正常写入 |

### 2.2 每周检查

- 核对 `sys_login_log` 中失败登录是否异常聚集；
- 核对 `sys_oper_log` 表体积，按月归档/清理；
- 验证备份文件可用性（见第 4 节）；
- 检查 `uploads/` 过期文件（配置项 `file.expire.clean_days=30`）；
- 检查 `scene3d_access_log` 异常访问量。

## 3. 日志管理

### 3.1 业务日志（数据库）

| 表 | 内容 | 清理方式 |
|---|---|---|
| `sys_oper_log` | 写操作入参/出参/耗时 | 页面「操作日志 → 清空」或按时间删除 |
| `sys_login_log` | 登录成功/失败 | 页面「登录日志 → 清空」 |
| `task_log` | 定时任务执行记录 | 任务日志页删除 |
| `outer_api_request_log` | 外部接口调用 | 接口日志页删除 |
| `scene3d_access_log` | 3D 场景访问 | 访问日志页删除 |
| `bi_visit_log` | 大屏访问 | 访问记录页删除 |

### 3.2 应用日志

| 日志 | 位置 | 用途 |
|---|---|---|
| Django 控制台 | 启动终端 | 开发排障 |
| 未捕获异常 | `common/exception.py` 的 `logger.exception` | 定位 500 |
| Nginx access/error | `/var/log/nginx/` | 访问与上游错误 |
| 操作日志写失败 | `common/middleware.py` 的 logger | 不影响业务，但需关注 |

> 生产建议：Django 日志接入文件轮转（`RotatingFileHandler`）或集中采集（ELK/Loki），保留 30 天。

## 4. 备份与恢复

### 4.1 数据库备份（真实可执行）

```bash
# 全量备份
mysqldump -h 192.168.0.76 -u root -p --single-transaction \
  --routines --triggers gen_admin > /backup/gen_admin_$(date +%F).sql

# 压缩
gzip /backup/gen_admin_$(date +%F).sql
```

Windows：

```powershell
mysqldump -h 192.168.0.76 -u root -p --single-transaction gen_admin > D:\backup\gen_admin_20261105.sql
```

> 注意：系统内置的「数据备份」模块 `POST /api/backup/record/manual` 只写入模拟记录，**不会真正执行 mysqldump**，生产备份必须使用上面的命令或数据库自带工具。

### 4.2 附件备份

```bash
tar -czf /backup/uploads_$(date +%F).tar.gz /opt/app/uploads
```

Windows 可用 `Compress-Archive -Path uploads -DestinationPath D:\backup\uploads.zip`。

### 4.3 恢复步骤

```bash
# 1. 停应用
systemctl stop django-app
# 2. 建库（如需）
mysql -u root -p -e "CREATE DATABASE gen_admin DEFAULT CHARACTER SET utf8mb4;"
# 3. 导入
mysql -u root -p gen_admin < /backup/gen_admin_2026-11-05.sql
# 4. 恢复附件
tar -xzf /backup/uploads_2026-11-05.tar.gz -C /opt/app/
# 5. 启动并验证
systemctl start django-app
```

验证：`admin` 可登录、表数量 ≥ 92、首页接口 `code=200`。

### 4.4 备份策略建议

| 对象 | 频率 | 保留 |
|---|---|---|
| MySQL 全量 | 每日 02:00 | 7 天 |
| MySQL 全量 | 每周日 | 4 周 |
| 附件目录 | 每日增量、每周全量 | 4 周 |
| 配置文件 | 变更后 | 永久 |

## 5. 发布与回滚

### 5.1 发布流程

```bash
# 1. 拉取代码
git pull
# 2. 后端依赖
cd backend && source venv/bin/activate && pip install -r requirements.txt
# 3. 前端构建
cd frontend && npm install && npm run build
# 4. 配置检查
cd backend && python manage.py check
# 5. 数据库变更（仅当 SQL 有变更时）
mysql -u root -p gen_admin < docs/xxx.sql
python manage.py init_db
# 6. 重启后端
systemctl restart django-app
# 7. 重载 Nginx
nginx -t && systemctl reload nginx
```

### 5.2 发布后验证

| 检查 | 通过标准 |
|---|---|
| 登录 | `code=200`，菜单完整 |
| 首页 | `/api/home/overview/` 正常 |
| 3D | 场景列表、分享页正常 |
| 构建产物 | `dist/index.html` 存在且时间戳更新 |
| 错误率 | 5 分钟内无持续 5xx |

### 5.3 回滚

1. `git checkout` 到上一个稳定标签/提交；
2. 重新 `pip install` 与 `npm run build`；
3. 若数据库有结构变更，用备份恢复到变更前时间点（**先确认数据丢失范围**）；
4. 重启后端 + reload Nginx。

> 数据库回滚属于破坏性操作，必须先确认备份可用并通知业务方。

## 6. 附件与磁盘治理

| 项目 | 策略 |
|---|---|
| 上传路径 | `uploads/YYYYMM/`，uuid 文件名 |
| 去重 | 按 MD5 秒传 |
| 回收站 | 逻辑删除，可恢复 |
| 彻底删除 | 移除数据库记录 + 磁盘文件 |
| 过期清理 | 配置 `file.expire.clean_days`（默认 30 天，需外部定时任务执行） |
| 容量监控 | 每周 `du -sh uploads/`，超过阈值告警 |
| 大文件 | 单文件默认 10MB，白名单见 `wf_file_config`；如需调整改配置并同步 Nginx `client_max_body_size` |

## 7. 安全运维

| 项 | 建议 |
|---|---|
| `SECRET_KEY` | 生产替换为随机长字符串，禁止入库/入 Git |
| `DEBUG` | 必须 `False` |
| `ALLOWED_HOSTS` | 配置真实域名 |
| 数据库账号 | 最小权限，禁止 root |
| CORS | 由 `ALLOW_ALL` 改为域名白名单 |
| 管理员密码 | 首次部署后修改 `admin` 默认密码 |
| 附件上传 | 保持后缀白名单，必要时增加内容类型校验 |
| 安全策略 | 启用 `sec` 模块的 IP 黑白名单与限流配置（配置真实生效需在网关层落地） |
| 审计 | 保留 `sys_oper_log`、`sys_login_log` 至少 6 个月 |
| 依赖漏洞 | 每季度执行 `pip list --outdated` 与 `npm audit` |

## 8. 故障处置速查

| 现象 | 可能原因 | 处置 |
|---|---|---|
| 启动报 `FileNotFoundError: docs/xxx.sql` | `init_db.py` 绝对路径与当前目录不符 | 修改 `SQL_FILE` 等常量 |
| `init_db` 报「表不存在」 | 未先导入 `additional_module_init.sql` | 先执行该脚本再 `init_db` |
| 登录 401 | token 过期/未带 Authorization | 重新登录；检查前端拦截器 |
| 登录 403 | 角色缺按钮权限 | 角色管理勾选对应菜单/按钮 |
| 列表为空但库里有数据 | `is_deleted=1` 或状态过滤 | 查库确认；恢复数据 |
| 雪花 ID 前端变科学计数 | 未走统一渲染器 | 确认 `BigIntJSONRenderer` 生效 |
| 上传失败 | 超大小/后缀不在白名单 | 调 `wf_file_config` 或压缩文件 |
| 预览 404 | kkFileView 未启动/地址不对 | 启动服务并改 `file/views.py` 的固定地址 |
| 3D 页面空白 | three chunk 加载失败/模型地址不可达 | 查 Network、确认构建产物 |
| 分享页 404 | token 过期或场景未发布 | 重新生成分享链接 |
| 首页无数据 | 聚合接口异常/无权限 | 查 `/api/home/*` 响应与后端日志 |
| 主题不生效 | 本地缓存异常 | 清理 `localStorage` 后重试 |
| Nginx 404（刷新页面） | 未配置 History 回退 | `try_files $uri $uri/ /index.html` |
| 502 Bad Gateway | 后端未启动/端口不对 | 查后端进程与 `proxy_pass` |
