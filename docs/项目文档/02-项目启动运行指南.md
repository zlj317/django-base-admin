## 1. 环境要求

| 组件 | 版本要求 | 检查命令 | 说明 |
|---|---|---|---|
| Python | 3.10+（实测 3.13 可运行） | `python --version` | 依赖见 `backend/requirements.txt` |
| Node.js | 18+ | `node -v` / `npm -v` | 前端 Vite 5 |
| MySQL | 8.0+ | `mysql -V` | 字符集 `utf8mb4` |
| 浏览器 | Chrome / Edge 最新版 | — | 前端为 SPA，需要 History 模式回退 |
| 操作系统 | Windows / Linux / macOS | — | 注意 `init_db.py` 中的绝对路径 |

`backend/requirements.txt` 实际依赖：Django 4.2、djangorestframework、django-cors-headers、mysqlclient、PyMySQL、bcrypt、PyJWT、requests、openpyxl、python-dateutil。

> 前端依赖见 `frontend/package.json`：Vue 3、Vite 5、Element Plus、Arco Design Vue、vue-router 4、axios、three（3D 模块）。

## 2. 首次启动流程

```
① 启动 MySQL → ② 导入附加模块 SQL → ③ 修改 settings 数据库连接
→ ④ python manage.py init_db → ⑤ runserver 8000 → ⑥ npm run dev 5173 → ⑦ admin/123456 登录
```

顺序不能颠倒：`init_db` 在最后会执行各业务模块的 `seed_*()`，这些种子数据依赖 `additional_module_init.sql` 创建的 22 张扩展表；如果跳过第 ② 步，初始化会在文件/消息/公告等模块的种子阶段报「表不存在」。

## 3. 数据库连接配置

编辑 `backend/config/settings.py` 的 `DATABASES`：

| 配置项 | 仓库当前值 | 说明 |
|---|---|---|
| `ENGINE` | `django.db.backends.mysql` | MySQL 驱动 |
| `NAME` | `gen_admin` | 业务库名，`init_db` 会自动创建 |
| `USER` / `PASSWORD` | `root` / `root` | 内网开发默认值，生产必须改 |
| `HOST` | `192.168.0.76` | 远程开发库地址，本机可改 `127.0.0.1` |
| `PORT` | `3306` | 默认端口 |
| `OPTIONS.charset` | `utf8mb4` | 支持中文与 emoji |

同时确认：

- `TIME_ZONE = 'Asia/Shanghai'`、`USE_TZ = False`（手工 SQL 写入本地时间，避免时区差）；
- `JWT_CONFIG['EXPIRE'] = 2 小时`、`REFRESH_THRESHOLD = 30 分钟`；
- `CORS_ALLOW_ALL_ORIGINS = True` 仅适合开发环境。

手动建库命令（`init_db` 也会自动执行）：

```sql
CREATE DATABASE IF NOT EXISTS gen_admin
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
```

## 4. 初始化数据（init_db）

### 4.1 先导入附加模块表

```bash
mysql -u root -p gen_admin < docs/additional_module_init.sql
```

该脚本创建附加模块 22 张表并写入 `wf_file_config` 的 8 条默认配置（上传大小、白名单、存储方式、预览服务地址、水印开关、清理周期）。

### 4.2 执行 init_db

```bash
cd backend
python manage.py init_db
```

`init_db.py` 的真实执行顺序：

1. 连接 MySQL 实例并 `CREATE DATABASE IF NOT EXISTS gen_admin`；
2. 依次执行 4 个 SQL：
   - `docs/后台管理系统-初始化建表SQL.sql`（基础平台 13 张）
   - `docs/后台管理系统-工作流建表SQL.sql`（工作流 11 张）
   - `docs/new_features_init.sql`（增强功能 33 张）
   - `docs/scene3d_init.sql`（3D 可视化 13 张 + 演示数据）
3. 将 `admin` 密码重置为 `123456`（bcrypt）；
4. 写入基础菜单/按钮权限，并逐个调用 `seed_file / seed_msg / seed_notice / seed_task_sched / seed_report / seed_bi / seed_outer / seed_sys_no / seed_imprint / seed_backup / seed_dp / seed_dsm / seed_mon / seed_sec / seed_tenant / seed_wo / seed_cal / seed_kb / seed_scene3d`。

可重复执行：建表为 `IF NOT EXISTS`，菜单已存在时跳过；需要重建菜单时加 `--force-menus`：

```bash
python manage.py init_db --force-menus
```

> **路径注意**：`init_db.py` 中 `SQL_FILE`、`SQL_WORKFLOW_FILE`、`SQL_NEW_FEATURES`、`SQL_SCENE3D` 为 Windows 绝对路径（`d:\other\django-base-admin\docs\...`）。换机器或换目录后必须先改成实际路径，否则会报 `FileNotFoundError`。

### 4.3 表数量核对

| 来源脚本 | 表数 |
|---|---|
| 后台管理系统-初始化建表SQL.sql | 13 |
| 后台管理系统-工作流建表SQL.sql | 11 |
| additional_module_init.sql | 22 |
| new_features_init.sql | 33 |
| scene3d_init.sql | 13 |
| **合计** | **92** |

完整字段字典见 [数据库设计与数据字典](./05-数据库设计与数据字典.md)。

## 5. 启动后端

```bash
cd backend
python -m venv venv
# Windows PowerShell
.\venv\Scripts\Activate.ps1
# macOS / Linux
# source venv/bin/activate

pip install -r requirements.txt
python manage.py check          # 建议先做配置检查
python manage.py runserver 0.0.0.0:8000
```

后端默认地址 `http://127.0.0.1:8000`，所有接口以 `/api/` 开头。开发期 `DEBUG = True`、`ALLOWED_HOSTS = ['*']`。

> 本项目未使用 Django Migration，模型 `managed = False`，不要执行 `makemigrations/migrate`；表结构统一由 SQL 脚本维护。

---

## 6. 启动前端

```bash
cd frontend
npm install
npm run dev
```

- 开发地址：`http://localhost:5173`
- `/api` 代理目标：`http://127.0.0.1:8000`（见 `frontend/vite.config.js`）
- 生产构建：`npm run build`，产物在 `frontend/dist/`

> 3D 模块的 `three` 通过动态 import 拆成独立 chunk，构建时会看到单独的 three 产物，属正常现象。

## 7. 启动验证

### 7.1 后端接口自检

```bash
curl -X POST http://127.0.0.1:8000/api/auth/login \
  -H "Content-Type: application/json" \
  -d "{\"username\":\"admin\",\"password\":\"123456\"}"
```

成功响应结构（HTTP 状态恒为 200）：

```json
{
  "code": 200,
  "msg": "登录成功",
  "data": {
    "token": "<JWT>",
    "user": { "id": "...", "username": "admin", "nickname": "超级管理员", "avatar": null },
    "perms": ["*:*:*"],
    "menus": []
  }
}
```

带令牌访问：

```bash
curl http://127.0.0.1:8000/api/system/user/list \
  -H "Authorization: Bearer <token>"
```

### 7.2 前端自检

1. 打开 `http://localhost:5173`，应跳转登录页；
2. `admin / 123456` 登录后进入首页 Dashboard，侧边栏出现全部已授权菜单；
3. 打开浏览器开发者工具，确认无 401、无 `/api` 代理报错；
4. 切换主题（顶栏「主题设置」）后刷新，主题应保持。

### 7.3 3D 模块专项

| 检查项 | 预期 |
|---|---|
| 菜单「3D可视化」 | 出现场景分类、3D场景管理、模型资源、数据绑定、告警联动、巡检路线、场景发布等页面 |
| 新建场景并保存 | `/api/scene3d/{id}/save` 返回 200，场景对象可持久化 |
| 发布场景 | 无对象时提示「场景暂无对象，无法发布」；有对象时生成版本 |
| 分享页 | `/scene3d/share/<token>` 免登录可打开已发布场景 |

## 9. 生产环境注意事项

- 修改 `SECRET_KEY`，关闭 `DEBUG`，`ALLOWED_HOSTS` 改为真实域名；
- `CORS_ALLOW_ALL_ORIGINS` 改为白名单；
- 数据库账号改用最小权限账号，密码通过环境变量注入；
- 后端用 Gunicorn / Waitress + Nginx，前端 `npm run build` 后静态托管，Nginx 需配置 `try_files ... /index.html` 以支持 History 路由；
- 附件默认保存到本地 `uploads/`，需纳入备份策略；对象存储、预览服务当前为配置预留，详见 [中间件配置与安装](./03-中间件配置与安装.md)；
- 完整多平台部署步骤见 [多平台部署指南](./04-多平台部署指南.md) 与 [运维手册](./07-运维手册.md)。
