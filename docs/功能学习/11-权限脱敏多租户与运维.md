### 公共机制：一个 CRUD 请求的完整生命周期

```python
class CrudViewSet(viewsets.ViewSet):
    model = None              # 子类指定模型类（≈ JPA Entity + Repository）
    serializer_class = None   # 子类指定序列化器（≈ DTO + Validator）
    perm_prefix = ''          # 权限前缀，如 system:user
    filter_map = {}           # 查询参数到 ORM lookup 的映射
    order_by = 'id'           # 默认排序
    module_name = ''          # 操作日志模块名

    @property
    def permission_classes(self):
        prefix = self.perm_prefix  # 取子类配置的权限前缀
        self.perm_map = {
            'list': f'{prefix}:list',      # 列表查询权限
            'create': f'{prefix}:create',  # 新增权限
            'update': f'{prefix}:update',  # 编辑权限
            'delete': f'{prefix}:delete',  # 删除权限
        }
        return [PermissionCheck]  # 登录校验已在 PermissionCheck 内部完成

    def get_queryset(self):
        # 逻辑删除条件在此统一收敛：只查 is_deleted=0
        return self.model.objects.filter(is_deleted=0).order_by(self.order_by)

    def apply_filters(self, queryset, request):
        for param, lookup in self.filter_map.items():
            value = request.query_params.get(param)  # 取前端传入的筛选值
            if value not in (None, ''):               # 空串/null 视为不过滤
                # 动态拼成 permission_name__icontains 这类 ORM lookup
                queryset = queryset.filter(**{f'{param}__{lookup}': value})
        return queryset

    def list(self, request):
        queryset = self.apply_filters(self.get_queryset(), request)  # 先过滤
        # 再统一分页 + 序列化，返回 {code,msg,data:{total,page,page_size,list}}
        return StandardPagination(request).paginate(queryset, self.get_serializer_class())
```

（以上见 `backend/common/views.py:11-61`）

对应到 Java：

- `ViewSet` 相当于 `@RestController` + 一组 `@GetMapping/@PostMapping`；
- `Serializer` 相当于 DTO + Bean Validation，`is_valid(raise_exception=True)` 相当于 `@Valid`；
- `Model.objects.filter(...)` 相当于 `JpaRepository` + Specification；
- `filter_map` 相当于把 `@RequestParam` 动态转成 `Specification`；
- `PermissionCheck` 相当于 HandlerInterceptor / Spring Security 的 `@PreAuthorize`；
- `StandardPagination` 相当于 PageHelper 的 `PageInfo`。

### 公共机制：权限校验

```python
class PermissionCheck(LoginRequired):
    def has_permission(self, request, view):
        if not super().has_permission(request, view):  # 先校验登录，未登录抛 401
            return False
        perm_map = getattr(view, 'perm_map', None)      # 视图声明的 action→权限标识
        if not perm_map:
            return True                                 # 未声明映射视为无需细粒度权限
        required = perm_map.get(view.action)            # 当前 action 需要的权限标识
        if not required:
            return True                                 # 该 action 未配置权限要求，直接放行
        perms = get_user_perms(request.user_info)       # 查用户权限集合（请求级缓存）
        if '*:*:*' in perms or required in perms:       # 超管通配或明确授权
            return True
        raise drf_exceptions.PermissionDenied(f'没有操作权限：{required}')  # 403
```

（`backend/common/permissions.py:43-59`。权限集合由一条“用户-角色-菜单”三表 JOIN 的 SQL 查出，见同文件 18-40 行；`role_key='admin'` 的用户自动拥有 `*:*:*`。）

def download(self, request, pk=None):

        'backup_status': row.backup_status,

## 模块小结

1. 六个模块全部复用 `CrudViewSet`：`list` 统一“逻辑删除过滤 → filter_map 动态筛选 → count+切片分页 → 序列化”，`create` 统一“唯一键预检查 → 序列化校验 → 补审计字段 → 落库”，`delete` 统一按 `ids` 批量处理，`status` 统一按 `status/enabled` 启停。理解这一套基类后，六个模块的视图代码几乎没有新知识。
2. 前端所有页面都遵循同一套模板：`query + query_orig` 管理筛选与重置、`fetchList` 统一拉列表、`openCreate/openEdit` 复用同一弹窗、`submitForm` 按 `id` 分流 create/update、删除用 `{data:{ids:[...]}}`。
3. 权限链路是“JWT → request.user_info → PermissionCheck → perm_map → 用户权限集合（含 admin 的 `*:*:*`）”；按钮权限由 `sys_menu.perms` 配置，视图的 `perm_prefix` 必须与种子权限字符串完全一致。
4. 主键统一为雪花 ID（`SnowflakeIDField`），JSON 渲染器会把超出 JS 安全整数范围的值转字符串；前端不要用 `parseInt` 后再回传，否则会丢精度。
5. 这些模块中，“数据权限”“脱敏”“限流”“备份策略”目前主要是配置管理：真实的数据过滤执行、字段掩码执行、限流拦截、Cron 调度都没有实现；备份的手动/下载是模拟实现，只落记录与元信息。
6. 数据表全部 `managed = False`，表结构由 `docs/数据库/*.sql` 手工创建，Django 不生成迁移；改字段必须同步改 SQL。
