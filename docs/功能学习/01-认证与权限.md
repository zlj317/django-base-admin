# 01 认证与权限：登录、令牌、登录态与按钮权限

## 1. 先建立全局地图

登录链路涉及的前后端文件：

### 1.1 后端统一响应：为什么前端总能拿到 `res.data`

[response.py](file:///d:/other/django-base-admin/backend/common/response.py#L29-L38) 定义：

```python
def ok(data=None, msg='success'):
    """成功响应：业务码固定 200，data 可以是对象、列表或 None。"""
    return Response({'code': 200, 'msg': msg, 'data': data})  # HTTP 状态保持 200，业务码由 body 承载


def fail(msg='error', code=500, data=None):
    """失败响应：自定义业务码与提示文案，便于前端按 code 分支处理。"""
    return Response({'code': code, 'msg': msg, 'data': data})  # 同样不改 HTTP 状态，保持统一解析方式
```

关键点：

- HTTP 状态码几乎永远是 200，真正的成功/失败看响应体 `code`。
- `BigIntJSONRenderer` 会把超过 JS 安全整数的雪花主键转成字符串（[response.py](file:///d:/other/django-base-admin/backend/common/response.py#L8-L26)），这是本项目所有列表/详情接口的全局行为。
- Java 类比：相当于统一返回 `Result<T>{ code, msg, data }`，再由 Jackson 的序列化定制把 `Long` 转 `String`。

### 1.2 前端统一请求：token 在哪里被带上

[request.js](file:///d:/other/django-base-admin/frontend/src/utils/request.js#L14-L32)：

```js
// 统一响应结构：{ code, msg, data }；code=200 成功；401 未登录；403 无权限；500 失败
// baseURL 固定为 /api：开发期由 Vite 代理转发到 Django，生产期由 Nginx 同域转发
const service = axios.create({
  baseURL: '/api',
  // 30 秒超时：覆盖大部分报表/导入类接口，又不会让用户长时间无响应
  timeout: 30000
})

// 请求拦截：自动携带 token
// 统一在这里注入，业务代码就不必每次手写 Authorization，也避免漏写导致 401
service.interceptors.request.use(
  config => {
    if (auth.token) {
      config.headers.Authorization = 'Bearer ' + auth.token
    }
    // 必须返回 config，否则 axios 拿不到请求配置
    return config
  },
```

因此页面里的 `/auth/login` 实际请求是 `POST /api/auth/login`，并且登录后所有请求自动带 `Authorization: Bearer <token>`。Java 类比：`RestTemplate` + `ClientHttpRequestInterceptor`，或 Feign 的 `RequestInterceptor`。

## 2. 示例 1：账号密码登录，签发 JWT 并返回菜单权限

### 2.1 前端触发位置

- 页面：[login/index.vue](file:///d:/other/django-base-admin/frontend/src/views/login/index.vue#L153-L175) 的 `handleLogin()`。
- 真正的接口调用不在页面里，而在 [store/auth.js](file:///d:/other/django-base-admin/frontend/src/store/auth.js#L63-L78) 的 `login(data)`。

页面先做表单校验，再调用 store：

```vue
<script setup>
// 登录主流程：校验通过后调用接口，成功则跳转，失败由拦截器提示
async function handleLogin() {
  // 无回调形式调用 validate：校验不通过会 reject，因此这一行若失败会中断后续流程
  await formRef.value.validate()
  // 校验通过，进入请求中状态（按钮转圈并禁止重复点击）
  loading.value = true
  try {
    // store 的 login 负责请求后端、写入 token 与用户信息，失败时抛出异常
    await login(form)
    // 登录成功提示（store 内不弹提示，因此在这里提示一次）
    ElMessage.success('登录成功')
    // 优先回到被守卫拦截前的目标页（如超时后重新登录），否则默认去首页
    const redirect = route.query.redirect || '/dashboard'
    // String(redirect) 处理 query 可能是数组的情况，保证传参类型正确
    router.push(String(redirect))
  } catch (e) {
    // 错误提示已由 request 拦截器统一处理
  } finally {
    // 无论成功失败都解除 loading，保证按钮可再次点击
    loading.value = false
  }
}
</script>
```

### 2.2 前端接口调用

[store/auth.js](file:///d:/other/django-base-admin/frontend/src/store/auth.js#L63-L78)：

```js
// 登录：调用后端换取 token，并一次性拿到用户、权限、菜单，减少登录后的串行请求
export async function login(data) {
  const res = await request.post('/auth/login', data)
  // res.data 是后端统一响应中的业务数据；兜底为空对象避免解构报错
  const d = res.data || {}
  // 先落 token，后续请求头才能自动携带
  setToken(d.token)
  auth.user = d.user || {}
  auth.perms = d.perms || []
  auth.menus = d.menus || []
  // 登录接口已经返回了完整信息，标记为已加载，路由守卫不必再请求 userinfo
  auth.loaded = true
  // 用户信息写入缓存，下次刷新可先展示
  localStorage.setItem(USER_KEY, JSON.stringify(auth.user))
  return d
}
```

请求参数就是页面的 `form`：`{ username, password }`。`request.js` 会自动加 `Content-Type: application/json`，并把响应解包成 `{code,msg,data}`；`code !== 200` 时拦截器直接 reject。

### 2.3 后端链路

1. [config/urls.py](file:///d:/other/django-base-admin/backend/config/urls.py#L5) 把 `/api/auth/` 挂到 `apps.system.urls_auth`。
2. [urls_auth.py](file:///d:/other/django-base-admin/backend/apps/system/urls_auth.py#L10-L14) 定义：

```python
urlpatterns = [  # 认证相关路径：登录、当前用户信息、退出
    path('login', login_view),  # 登录接口
    path('userinfo', userinfo_view),  # 用户信息接口
    path('logout', logout_view),  # 退出接口
```

其中 `login_view = AuthViewSet.as_view({'post': 'login'})`，只允许 POST。

3. 视图：[auth.py](file:///d:/other/django-base-admin/backend/apps/system/views/auth.py#L56-L93) 的 `AuthViewSet.login`。

```python
class AuthViewSet(viewsets.ViewSet):
    """认证视图集合：登录、用户信息、退出。"""
    module_name = '认证管理'  # 操作日志模块名
    permission_classes = []  # 登录接口自行控制

    def get_permissions(self):
        """按动作返回权限：除登录外均需登录态。"""
        # userinfo/logout 需要登录（get_permissions 需返回实例，DRF 不会自动实例化）
        if self.action != 'login':
            return [LoginRequired()]  # 非登录接口校验令牌
        return []  # 登录接口放行

    def login(self, request):
        """账号密码登录：校验、记录日志、签发令牌并返回菜单权限。"""
        username = (request.data.get('username') or '').strip()  # 去除首尾空白
        password = (request.data.get('password') or '')  # 原始密码
        ip = get_client_ip(request)  # 客户端 IP
        browser = request.META.get('HTTP_USER_AGENT', '')  # 浏览器 UA

        if not username or not password:  # 必填校验
            return fail('请输入用户名和密码')  # 参数缺失
        user = SysUser.objects.filter(username=username, is_deleted=0).first()  # 查未删除用户
        if not user or not check_password(password, user.password):  # 用户不存在或密码错误
            login_log(username, ip, 1, '用户名或密码错误', browser)  # 记录失败日志
            return fail('用户名或密码错误')  # 返回失败
        if user.status:  # 状态为 True 表示已禁用
            login_log(username, ip, 1, '账号已被禁用', browser)  # 记录失败日志
            return fail('账号已被禁用，请联系管理员')  # 返回禁用提示

        login_log(username, ip, 0, '登录成功', browser)  # 记录成功日志
        data = {  # 登录成功返回结构：令牌 + 基础用户 + 权限标识 + 菜单树
            'token': create_token(user),  # 签发访问令牌
            'user': {'id': user.id, 'username': user.username,  # 返回基础用户信息
                     'nickname': user.nickname, 'avatar': user.avatar},  # 昵称与头像
            'perms': get_user_perms(user),  # 权限标识
            'menus': get_user_menus(user),  # 侧边栏菜单树
        }
        return ok(data, '登录成功')  # 统一成功响应
```

业务步骤拆解：

1. `request.data` 是 DRF 解析后的请求体（JSON → dict），等价于 Spring 的 `@RequestBody Map`。
2. 账号必须未逻辑删除：`is_deleted=0`。这是全项目统一的软删除字段。
3. 密码不是明文比较，而是 `bcrypt.checkpw`：[utils.py](file:///d:/other/django-base-admin/backend/common/utils.py#L11-L16)。
4. 登录成功与失败都写 `sys_login_log`，失败原因会截断到表长度：[auth.py](file:///d:/other/django-base-admin/backend/apps/system/views/auth.py#L48-L53)。
5. `create_token` 用 PyJWT 签名，载荷只有 `uid/username/exp`：[common/auth.py](file:///d:/other/django-base-admin/backend/common/auth.py#L18-L26)。

```python
def create_token(user):
    """为模型实例或字典形式用户签发 JWT，载荷包含 uid/username/exp。"""
    cfg = settings.JWT_CONFIG  # 取配置，避免在函数内硬编码密钥与算法
    payload = {  # 载荷保持精简，只放认证与展示所需字段
        'uid': user['id'] if isinstance(user, dict) else user.id,  # 兼容字典与模型两种入参
        'username': user['username'] if isinstance(user, dict) else user.username,  # 同上，便于日志展示
        'exp': int(time.time() + cfg['EXPIRE'].total_seconds()),  # 秒级过期时间戳，由 PyJWT 自动校验
    }
    return jwt.encode(payload, cfg['SECRET'], algorithm=cfg['ALGORITHM'])  # 对称签名，返回字符串 token
```

配置在 [settings.py](file:///d:/other/django-base-admin/backend/config/settings.py#L103-L109)：有效期 2 小时，剩余不足 30 分钟时中间件会下发新 token。

### 2.4 菜单与权限是如何算出来的

`get_user_menus(user)` 先查角色：

```python
def get_user_menus(user):
    """侧边栏菜单树（M/C 类型），超管返回全部。"""
    role_keys = {key for _, key in get_user_role_ids(user)}  # 当前用户角色编码集合
    qs = SysMenu.objects.filter(is_deleted=0, status='0', menu_type__in=['M', 'C'], visible='0')  # 可见菜单
    if 'admin' not in role_keys:  # 非超管按角色授权过滤
        from django.db import connection  # 延迟导入，避免模块级依赖
        with connection.cursor() as cursor:  # 查询角色-菜单关联表
            cursor.execute(
                "SELECT DISTINCT rm.menu_id FROM sys_user_role ur "  # 用户-角色关联
                "JOIN sys_role_menu rm ON rm.role_id = ur.role_id WHERE ur.user_id = %s",  # 聚合角色菜单
                [user.id])
            menu_ids = [r[0] for r in cursor.fetchall()]  # 已授权菜单ID
        qs = qs.filter(id__in=menu_ids)  # 仅保留已授权菜单
    rows = list(qs.values('id', 'parent_id', 'menu_name', 'path', 'component',  # 只取菜单展示所需字段
                          'menu_type', 'icon', 'order_num', 'visible', 'status'))
    return build_tree(rows)  # 组装为前端可用的树结构
```

`build_tree` 在 [utils.py](file:///d:/other/django-base-admin/backend/common/utils.py#L19-L38)，把扁平列表按 `parent_id` 组装成 `children` 树；孤儿节点、自引用节点都按根处理，避免死循环。

权限码 `perms` 来自 `PermissionCheck` 的同一套 SQL：[permissions.py](file:///d:/other/django-base-admin/backend/common/permissions.py#L11-L40)。角色 `role_key='admin'` 直接获得 `*:*:*` 通配。

## 3. 示例 2：获取当前用户信息并按需续签令牌

### 3.1 前端触发

刷新页面后，路由守卫 [router/index.js](file:///d:/other/django-base-admin/frontend/src/router/index.js#L222-L262) 发现 `auth.loaded=false`，调用 `ensureUserLoaded()`：

```js
if (!auth.loaded) {
  try {
    await ensureUserLoaded()
  } catch (e) {
    // 拉取失败通常意味着 token 失效：清空本地状态并回登录页，避免带着脏状态继续访问
    resetAuth()

  }

```

[store/auth.js](file:///d:/other/django-base-admin/frontend/src/store/auth.js#L80-L102)：

```js
export async function fetchUserinfo() {
  const res = await request.get('/auth/userinfo')
  const d = res.data || {}
  // 后端可能在响应中续签 token，此时同步更新本地，实现无感续期
  if (d.token) {
    setToken(d.token)
  }
  auth.user = d.user || {}
  auth.perms = d.perms || []
  auth.menus = d.menus || []
  auth.loaded = true
  localStorage.setItem(USER_KEY, JSON.stringify(auth.user))
  return d
}

export function ensureUserLoaded() {
  if (auth.loaded) return Promise.resolve()
  return fetchUserinfo()
}
```

### 3.2 后端链路

- 路由：`GET /api/auth/userinfo` → `AuthViewSet.userinfo`（[auth.py](file:///d:/other/django-base-admin/backend/apps/system/views/auth.py#L95-L105)）。
- 认证：DRF 全局配置 `DEFAULT_AUTHENTICATION_CLASSES = ['common.auth.JWTAuthentication']`（[settings.py](file:///d:/other/django-base-admin/backend/config/settings.py#L92-L101)）。

```python
class JWTAuthentication(BaseAuthentication):
    """从 Authorization: Bearer <token> 解析用户，失败抛 AuthFailed（code 401）。"""

    def authenticate(self, request):
        """解析请求头中的 token；无凭证返回 None，成功返回 (用户, 载荷)。"""
        auth = get_authorization_header(request).split()  # 拆成 [认证方案, token] 两段
        if not auth or auth[0].lower() != b'bearer':
            return None  # 非 Bearer 方案视为未认证，交给后续认证类处理
        if len(auth) != 2:
            raise AuthFailed('token 格式错误')  # 缺少 token 或多段内容都属格式错误
        token = auth[1].decode()  # 字节转字符串，PyJWT 只接受 str
        try:
            payload = decode_token(token)  # 解析并验证签名与有效期
        except jwt.ExpiredSignatureError:
            raise AuthFailed('登录已过期，请重新登录')  # 过期单独提示，前端可引导重新登录
        except jwt.InvalidTokenError:
            raise AuthFailed('无效的登录凭证')  # 签名错误、被篡改等统一提示

        from apps.system.models import SysUser  # 延迟导入，避免与应用初始化顺序耦合
        user = SysUser.objects.filter(id=payload['uid'], is_deleted=0, status=0).first()  # 只认未删除且启用的账号
        if not user:
            raise AuthFailed('用户不存在或已被禁用')  # 账号删除/禁用后旧 token 立即失效
        request.user_info = user  # 挂到 DRF request，供视图与权限类使用
        request.jwt_payload = payload  # 挂原始载荷，续期中间件需要其中的 exp
        request._request.user_info = user  # 中间件拿到的是原生 HttpRequest，只能从这里读取
        request._request.jwt_payload = payload  # 同上，保证两处引用一致
        return (user, payload)  # DRF 约定二元组，第二项可通过 request.auth 访问
```

### 3.3 续签中间件

[auth.py](file:///d:/other/django-base-admin/backend/apps/system/views/auth.py#L95-L105) 只负责重新下发用户信息；真正的响应头续签在 [middleware.py](file:///d:/other/django-base-admin/backend/common/middleware.py#L100-L123)：

```python
class TokenRefreshMiddleware:
    """token 剩余有效期不足阈值时，在响应头下发新 token（X-Refresh-Token）。"""

    def __call__(self, request):
        """响应返回前判断剩余有效期，必要时续期并写入响应头。"""
        response = self.get_response(request)  # 先让业务处理完，确保 jwt_payload 已挂载
        payload = getattr(request, 'jwt_payload', None)  # 认证类挂载的载荷，未登录时为 None
        if payload and 'exp' in payload:
            from datetime import datetime, timedelta
            from django.conf import settings
            from common.auth import create_token

            remain = datetime.fromtimestamp(payload['exp']) - datetime.now()  # 本地时间下的剩余有效期
            threshold = settings.JWT_CONFIG['REFRESH_THRESHOLD']  # 配置的续期阈值
            if remain < threshold and remain.total_seconds() > 0:
                user = getattr(request, 'user_info', None)
                if user is not None:
                    response['X-Refresh-Token'] = create_token(user)  # 前端读取该头后替换本地 token
        return response
```

前端在 [request.js](file:///d:/other/django-base-admin/frontend/src/utils/request.js#L46-L51) 读取该响应头：

```js
// 静默续期：若响应头携带 X-Refresh-Token 则更新本地 token
const newToken = response.headers && response.headers['x-refresh-token']
if (newToken) {
  setToken(newToken)
}
```

### 3.4 数据表与 ORM

`userinfo` 本身只读 `sys_user`，再复用示例 1 的菜单/权限查询。`SysUser.objects.filter(id=payload['uid'], is_deleted=0, status=0)` 是最小必要查询：一次 SQL 完成“存在 + 未删除 + 启用”三项校验。

### 3.5 Java 对照

- `JWTAuthentication` ≈ `OncePerRequestFilter` + `SecurityContextHolder.setAuthentication(...)`。
- `request.user_info` ≈ `SecurityContext.getAuthentication().getPrincipal()`。
- `TokenRefreshMiddleware` ≈ 响应包装 Filter，在 `chain.doFilter` 之后改响应头。
- Django 中间件顺序在 `MIDDLEWARE` 中声明，越靠前越外层，与 Servlet Filter 链一致。

## 4. 示例 3：退出登录

### 4.1 前端触发

顶部栏调用 [store/auth.js](file:///d:/other/django-base-admin/frontend/src/store/auth.js#L104-L114) 的 `logout()`：

```js
export async function logout() {
  try {
    // 通知后端注销会话（例如清理 Redis 中的 token）；后端失败不应阻止前端退出
    await request.post('/auth/logout')

    // 忽略登出接口异常，本地状态照样清理
  }
  // 无论接口是否成功都清空本地，避免用户“点了退出却还处于登录态”
  resetAuth()
}
```

### 4.2 后端

[urls_auth.py](file:///d:/other/django-base-admin/backend/apps/system/urls_auth.py#L8) 同时接受 POST/DELETE：


视图 [auth.py](file:///d:/other/django-base-admin/backend/apps/system/views/auth.py#L107-L109)：

```python
def logout(self, request):
```

本项目 JWT 无状态，服务端不维护 token 黑名单；安全性依赖“前端删除 token + token 两小时过期”。如果需要服务端强制失效，应增加 Redis 黑名单并在 `JWTAuthentication` 中校验。

## 5. 示例 4：token 持久化、路由守卫与 401 统一处理

### 5.1 前端触发位置

- 守卫：[router/index.js](file:///d:/other/django-base-admin/frontend/src/router/index.js#L222-L262)。
- 401 处理：[request.js](file:///d:/other/django-base-admin/frontend/src/utils/request.js#L53-L72)。
- token 持久化：[store/auth.js](file:///d:/other/django-base-admin/frontend/src/store/auth.js#L38-L47)。

### 5.2 守卫逻辑

```js
// 全局前置守卫：负责登录校验、用户信息预加载、字典预热与动态路由注入
router.beforeEach(async to => {
  // 已登录访问登录页 → 跳首页
  if (to.path === '/login') {
    return auth.token ? { path: '/dashboard' } : true
  }
  // 3D 场景分享页：免登录访问（后端 share/<token> 接口为 AllowAny）
  if (to.path.startsWith('/scene3d/share/')) return true
  // 未登录 → 跳登录页，并记录原目标地址
  if (!auth.token) {
    return {
      path: '/login',
      query: to.fullPath && to.fullPath !== '/' ? { redirect: to.fullPath } : {}
    }
  }
  // 首次加载：拉取用户信息、权限、菜单
  if (!auth.loaded) {
    try {
      await ensureUserLoaded()
    } catch (e) {
      resetAuth()
      return { path: '/login' }
    }
  }
  // 拉取字典缓存（不阻塞跳转）
  loadDicts()
  // 动态路由尚未注册时，先注册再重新解析目标地址
  if (!dynamicAdded) {
    addDynamicRoutes()
    return { path: to.path, query: to.query, hash: to.hash, replace: true }
  }
  return true
})
```

为什么需要“重新解析一次”：首次导航时动态路由还没注册，`to` 命中的是通配 404；`addDynamicRoutes()` 把菜单转成路由后，必须按原 path 再匹配一次，否则会停在 404。

### 5.3 401 处理

```js
// 登录态失效：清理内存与本地存储，提示后跳转登录页
if (res.code === 401) {
  resetAuth()
  ElMessage.error(res.msg || '登录已过期，请重新登录')
  // 已经在登录页时不再跳转，避免重复导航造成的路由抖动
  if (router.currentRoute.value.path !== '/login') {
    router.push('/login')
  }
}
```

后端 401 来自 [exception.py](file:///d:/other/django-base-admin/backend/common/exception.py#L11-L15)：`NotAuthenticated` / `AuthenticationFailed` 都映射为业务码 401，HTTP 状态仍为 200。

## 6. 示例 5：动态路由与 v-perm 按钮权限

### 6.1 后端下发菜单

登录/`userinfo` 返回的 `menus` 是树结构，节点字段包含 `menu_type`：

- `M`：目录，只做分组；
- `C`：菜单/页面，前端生成真实路由；
- `F`：按钮，只用于 `perms`，不生成页面路由。

### 6.2 前端菜单转路由

[router/index.js](file:///d:/other/django-base-admin/frontend/src/router/index.js#L137-L210)：

```js
function collectLeaves(menus, prefix, leaves) {
  ;(menus || []).forEach(menu => {
    // menu_type === 'C' 表示“页面/组件”类菜单，它才会真正生成一条可访问的路由
    if (menu.menu_type === 'C') {
      const comp = resolveComponent(menu.component)
      // 组件找不到说明菜单配置有误（或页面已删除），直接跳过
      if (!comp) return
      leaves.push({
        // 拼接完整访问路径：父目录路径 + 当前菜单 path
        path: prefix ? prefix + '/' + menu.path : menu.path,
        name: 'menu-' + menu.id,
        component: comp,
        meta: { title: menu.menu_name, icon: menu.icon }
      })
    } else if (menu.menu_type === 'M' && menu.children) {
      // 'M' 是目录节点：本身不产生页面，只把路径前缀往下传并继续递归
      collectLeaves(menu.children, prefix ? prefix + '/' + menu.path : menu.path, leaves)
    }
  })
}
```

`resolveComponent` 用 `import.meta.glob('../views/**/*.vue')` 预扫描所有页面，后端只存 `component='system/user/index'`，前端按约定拼路径。Java 类比：后端返回菜单 JSON，前端按约定字符串做 `Class.forName` 式的组件解析。

### 6.3 按钮权限指令

[perm.js](file:///d:/other/django-base-admin/frontend/src/directive/perm.js#L8-L33)：

```js
export const perm = {
  mounted(el, binding) {
    // 元素刚插入 DOM 时立即判断一次，避免先显示再隐藏造成闪烁
    check(el, binding)
  },
  updated(el, binding) {
    // 权限列表可能在用户信息刷新后变化，更新时再判断一次以同步状态
    check(el, binding)
  }
}

function check(el, binding) {
  const value = binding.value
  // 未绑定权限值视为“不需要控制”，保持元素原样
  if (value === undefined || value === null || value === '') return
  if (!hasPerm(value)) {
    // 用 dataset 打标记而不是直接删除 DOM，便于 updated 时精确还原 display
    el.dataset.permHidden = '1'
    el.style.display = 'none'
  } else if (el.dataset && el.dataset.permHidden === '1') {
    delete el.dataset.permHidden
    el.style.display = ''
  }
}
```

页面用法（[system/user/index.vue](file:///d:/other/django-base-admin/frontend/src/views/system/user/index.vue#L69-L71)）：

```vue
<!-- 新增：需 system:user:create；无权限时 v-perm 指令直接隐藏元素 -->
<el-button v-perm="'system:user:create'" type="primary" :icon="Plus" @click="openCreate">新增</el-button>
<!-- 批量删除：需 system:user:delete；plain 弱化危险色块；未选中任何行时禁用 -->
<el-button v-perm="'system:user:delete'" type="danger" plain :icon="Delete" :disabled="!selection.length" @click="handleBatchDelete">批量删除</el-button>
```

### 6.4 后端权限校验

真正的安全边界在接口层：[permissions.py](file:///d:/other/django-base-admin/backend/common/permissions.py#L43-L59)：

```python
class PermissionCheck(LoginRequired):
    """登录 + 权限标识校验。"""

    def has_permission(self, request, view):
        """先校验登录，再按 perm_map 比对用户权限，缺失即抛 403。"""
        if not super().has_permission(request, view):
            return False
        perm_map = getattr(view, 'perm_map', None)  # 视图声明的 action -> 权限标识映射
        if not perm_map:
            return True
        required = perm_map.get(view.action)  # 当前 action 对应的权限标识
        if not required:
            return True
        perms = get_user_perms(request.user_info)  # 取用户权限集合（已带缓存）
        if '*:*:*' in perms or required in perms:
            return True
        raise drf_exceptions.PermissionDenied(f'没有操作权限：{required}')
```

`perm_map` 由 `CrudViewSet.permission_classes` 动态生成（[common/views.py](file:///d:/other/django-base-admin/backend/common/views.py#L30-L40)）：`list/create/update/delete` 分别对应 `prefix:list/create/update/delete`。

### 6.5 Java 对照

- 前端 `v-perm` ≈ `@PreAuthorize("hasAuthority('system:user:create')")` 的“隐藏按钮”体验版。
- 后端 `PermissionCheck` ≈ `HandlerInterceptor` + `@PreAuthorize`。
- `perm_map` 的动态拼装 ≈ `@RequestMapping` 方法上的权限注解按 action 解析。

## 7. 本篇小结

- Django 的 URL 是“前缀 include + 子路由 path”，DRF 的 `ViewSet.as_view({'post':'login'})` 把 HTTP 方法映射到 Python 方法。
- 认证信息由 `JWTAuthentication` 解析后挂到 `request.user_info`；权限类在这之后做二次校验。
- 统一响应 `{code,msg,data}` 与全局异常处理器让前端只处理一种结构。
- 雪花主键由 `SnowflakeIDField` 在插入时生成，并由 `BigIntJSONRenderer` 转字符串。
- 前端 token 持久化、路由守卫、401 处理、按钮权限都在固定位置，新增页面无需重复实现。
