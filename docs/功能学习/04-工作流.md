## 模块职责

工作流模块负责「流程定义 + 流程运行」两件事，对应后端 App `backend/apps/workflow`：

1. **流程定义侧**：流程分类（`wf_category`）、自定义业务表单（`wf_form`）、固定审批小组（`wf_group`/`wf_group_user`）、BPMN 流程模型（`wf_model`）以及监听器（`wf_listener`）、表达式（`wf_expression`）等配置。
2. **流程运行侧**：按 BPMN XML 驱动流程实例（`wf_instance`）、生成人工待办（`wf_task`）、留痕（`wf_audit`）、抄送（`wf_cc`）。核心引擎位于 `backend/apps/workflow/engine.py`，自行解析 bpmn-js 导出的 XML，支持串行 / 或签 / 会签、排他网关、并行网关与退回上一节点。
3. **对外接口**：全部挂在 `/api/wf/` 下，由 `backend/config/urls.py:8` 引入 `apps.workflow.urls`；前端页面位于 `frontend/src/views/workflow/`，统一通过 `frontend/src/utils/request.js` 的 axios 实例访问（`baseURL=/api`，请求拦截器注入 `Authorization: Bearer <token>`）。

```python
@property
def permission_classes(self):
    """按 perm_prefix 动态生成 perm_map，并固定使用 PermissionCheck。"""
    prefix = self.perm_prefix  # 取子类配置的权限前缀
    self.perm_map = {
        'list': f'{prefix}:list',  # 列表查询权限
        'create': f'{prefix}:create',  # 新增权限
        'update': f'{prefix}:update',  # 编辑权限
        'delete': f'{prefix}:delete',  # 删除权限
    }
    return [PermissionCheck]  # 只挂自定义权限类，登录校验已在其内部完成
```

`PermissionCheck` 的执行顺序（`backend/common/permissions.py:43-58`）：

```python
class PermissionCheck(LoginRequired):
    """登录 + 权限标识校验。"""
    def has_permission(self, request, view):
        if not super().has_permission(request, view):
            return False  # 登录校验失败（内部已抛 401），此处仅兜底
        perm_map = getattr(view, 'perm_map', None)  # 视图声明的 action -> 权限标识映射
        if not perm_map:
            return True  # 未声明映射视为无需细粒度权限
        required = perm_map.get(view.action)  # 当前 action 对应的权限标识
        if not required:
            return True  # 该 action 未配置权限要求，直接放行
        perms = get_user_perms(request.user_info)  # 取用户权限集合（已带缓存）
        if '*:*:*' in perms or required in perms:
            return True  # 超管通配或已明确授权
        raise drf_exceptions.PermissionDenied(f'没有操作权限：{required}')
```

列表逻辑本身：

```python
def get_queryset(self):
    """返回过滤逻辑删除后的基础查询集，供各类操作复用。"""
    return self.model.objects.filter(is_deleted=0).order_by(self.order_by)  # 逻辑删除条件在此统一收敛

def apply_filters(self, queryset, request):
    """按 filter_map 把非空查询参数拼成 ORM 过滤条件。"""
    for param, lookup in self.filter_map.items():
        value = request.query_params.get(param)  # 取前端传入的筛选值
        if value not in (None, ''):
            queryset = queryset.filter(**{f'{param}__{lookup}': value})  # 动态拼接 ORM lookup
    return queryset  # 返回链式过滤后的查询集

def list(self, request):
    """列表接口：筛选 + 分页 + 序列化。"""
    queryset = self.apply_filters(self.get_queryset(), request)  # 先过滤再分页，保证 total 准确
    return StandardPagination(request).paginate(queryset, self.get_serializer_class())  # 输出统一分页结构
```

逐条说明：

- `is_deleted=0`：`BaseModel.is_deleted` 是 `BooleanField`，Django 对 SQLite/MySQL 都能用 `0` 比较；被逻辑删除的分类不会出现在列表。
- `order_by` 默认 `'id'`（`common/views.py:34`），但 `WfCategory.Meta.ordering = ['sort', 'id']` 被显式 `order_by('id')` 覆盖，见下方「疑似问题」。
- `apply_filters` 只在参数「非空」时拼接；前端传 `name=''`、`status=''` 时会被忽略，因此空串等价于不筛选。
- `icontains` 生成 `LIKE '%值%'`（大小写不敏感）；`exact` 生成 `=`。
- 分页在 `common/pagination.py:44-59`：

```python
def paginate(self, queryset, serializer_class=None, many=True):
    """统计总数并截取当前页，可选序列化后按统一结构返回。"""
    # count() 在切片前执行，Django 会据此生成独立 SELECT COUNT(*)，统计值不受后面的 LIMIT 影响。
    total = queryset.count()  # 先取总数，前端需要据此计算总页数
    # 对 QuerySet 切片等价于 SQL 的 LIMIT/OFFSET，只把当前页数据取回内存。
    rows = queryset[self.offset:self.offset + self.page_size]  # 只查当前页数据，避免全量加载
    # 四个字段名是前后端约定的分页协议，新增字段需要同步前端表格组件。
    data = {
        'total': total,  # 总记录数
        'page': self.page,  # 当前页码
        'page_size': self.page_size,  # 每页条数
        'list': serializer_class(rows, many=many).data if serializer_class else list(rows),  # 有序列化器则输出字典
    }
    # 统一包装：调用方（视图）直接 return，无需再关心响应格式。
    return ok(data)  # 统一包装成 {code, msg, data}
```

```python
def create(self, request):
    """新增接口：校验入参后补审计字段并回写完整对象。"""
    # 逻辑删除记录仍占用数据库唯一索引，新增前先给出明确提示，避免直接落库时报 500
    for field in self.model._meta.fields:
        if not field.unique or field.primary_key or not hasattr(self.model, 'is_deleted'):
            continue  # 只校验业务唯一字段
        value = request.data.get(field.attname)  # 取提交的唯一字段值
        if value in (None, ''):
            continue  # 未提交则交给序列化器处理
        qs = self.model.objects.filter(**{field.attname: value})  # 含已删除记录
        if qs.filter(is_deleted=0).exists():  # 未删除记录已占用
            return fail(f'{field.verbose_name}已存在', code=400)  # 明确提示
        if qs.exists():  # 仅被已删除记录占用（数据库唯一键冲突）
            return fail(f'{field.verbose_name}已被已删除记录占用，请更换{field.verbose_name}', code=400)
    serializer = self.get_serializer_class()(data=request.data)  # 绑定请求体做字段校验
    serializer.is_valid(raise_exception=True)  # 校验失败交给全局异常处理器转 400
    now = time.strftime('%Y-%m-%d %H:%M:%S')  # 统一时间格式，与手写 SQL 的写入方式保持一致
    user = getattr(request, 'user_info', None)  # 当前登录用户，用于审计字段
    audit = {}  # 仅对继承 BaseModel 的模型补审计字段，日志类模型无这些列
    if hasattr(self.model, 'create_by'):
        audit = dict(
            create_by=user.username if user else '',  # 未登录时留空（正常流程不会出现）
            create_time=now,  # 创建时间
            update_by=user.username if user else '',  # 初始更新人与创建人一致
            update_time=now,  # 初始更新时间
        )
    instance = serializer.save(**audit)  # 落库并返回带雪花主键的实例，供下一步回写完整数据
    self.after_create(request, instance)  # 子类可在此做关联数据写入
    return ok(self.get_serializer_class()(instance).data, '新增成功')  # 返回落库后的完整数据
```

逐条说明：

1. **唯一键友好提示**：`WfForm.form_key` 是 `unique=True`。数据库唯一索引会把「已逻辑删除」的行也计入，所以不能只靠 `is_deleted=0` 查询；这里先查全量，再区分「活跃记录占用」与「已删除记录占用」两种情况，分别返回 400 业务码。
2. **序列化器校验**：`ModelSerializer` 会按模型字段生成必填/长度校验；`raise_exception=True` 把错误抛给 `common/exception.py` 的全局处理器，HTTP 状态仍为 200、`code` 为 400。
3. **审计字段**：`create_by/update_by` 写用户名而不是雪花 ID，便于日志阅读；时间统一 `'%Y-%m-%d %H:%M:%S'`，与手写 SQL 的写入格式对齐。
4. **落库**：`serializer.save(**audit)` 等价于 INSERT；`id` 由 `SnowflakeIDField` 生成。
5. **返回**：再序列化一次落库后的实例，保证前端拿到 `id` 等回写字段。

注意：这里没有 `transaction.atomic()`，但新增只涉及一条 INSERT，失败会整体回滚到数据库层，不存在跨表半成品。

```python
def parse_json(text, default):
    """把数据库中的 JSON 文本解析为对象，失败时返回默认值。"""
    try:
        return json.loads(text) if text else default  # 空值直接返回默认值
    except (TypeError, ValueError):
        return default  # 脏数据不影响接口返回
```

保存成员：

```python
def set_users(self, request, pk=None):
    """覆盖式保存分组成员：先清空再写入提交的用户。"""
    group = self.get_queryset().filter(id=pk).first()  # 先确认分组存在
    if not group:  # 分组不存在
        return fail('分组不存在', code=404)
    user_ids = [int(x) for x in (request.data.get('user_ids') or []) if str(x).isdigit()]  # 过滤合法 ID
    WfGroupUser.objects.filter(group_id=group.id).delete()  # 覆盖式更新：先删旧关系
    now = time.strftime('%Y-%m-%d %H:%M:%S')  # 统一写入时间
    for uid in set(user_ids):  # 去重写入，避免重复关联
        WfGroupUser.objects.create(group_id=group.id, user_id=uid, create_time=now)  # 逐条 INSERT
    return ok({'user_ids': user_ids}, '成员保存成功')
```

逐条说明：

1. `group_id` 的合法性：先通过 `get_queryset()` 校验分组未删除，避免给已删除分组挂成员。
2. `str(x).isdigit()` 同时兼容前端传字符串和数字；非数字、空值、`None` 会被静默丢弃。
3. `set(user_ids)` 去重，但返回值仍是原始列表 `user_ids`（见「疑似问题」）。
4. `delete()` 是物理删除关联行（`WfGroupUser` 没有 `is_deleted`），随后逐条 `create`，整体语义是「全量覆盖」。
5. **没有包 `transaction.atomic()`**：删除成功但后续某条 INSERT 失败时，会出现「成员被清空但只写入一部分」的中间状态。数据库是 MySQL 时单条语句自动提交，这是潜在风险（见文末疑似问题）。
6. 没有维护 `wf_group.update_time`，列表上的成员数/成员标签来自序列化器实时统计，因此不影响展示。

保存设计：

```python
def save(self, request):
    """保存设计结果：更新 BPMN XML 与节点配置。"""
    pk = request.data.get('id')  # 模型 ID
    row = self.get_queryset().filter(id=pk).first()  # 模型
    if not row:  # 不存在
        return fail('模型不存在', code=404)
    xml = request.data.get('bpmn_xml') or ''  # 流程定义
    try:
        engine.ProcessGraph(xml)  # 保存前先解析，提前暴露错误 XML
    except engine.EngineError as exc:  # 解析失败
        return fail(str(exc))
    node_config = request.data.get('node_config') or {}  # 节点配置
    row.bpmn_xml = xml  # 写入 XML
    row.node_config = json.dumps(node_config, ensure_ascii=False)  # 写入配置
    row.update_by = request.user_info.username  # 更新人
    row.update_time = time.strftime('%Y-%m-%d %H:%M:%S')  # 更新时间
    row.save(update_fields=['bpmn_xml', 'node_config', 'update_by', 'update_time'])  # 只更新必要字段
    return ok({'id': row.id}, '设计保存成功')
```

逐条说明：

1. **只允许改已存在模型**：设计页不负责新建模型，新建走列表页的 `create`；`id` 缺失时 `filter(id=None)` 返回空集，直接 404。
2. **保存前校验 XML**：`engine.ProcessGraph(xml)` 构造时会解析 BPMN（详见 `engine.py:63-115` 的 `ProcessGraph.__init__`：校验 XML 语法、`process` 元素、至少一个可执行节点），不合法会抛 `EngineError`，因此不可能把语法错误或空流程存进库。开始节点是否存在要到运行期 `start()` 调用 `start_node()` 时才校验。
3. **节点配置序列化**：`json.dumps(..., ensure_ascii=False)` 保留中文节点名与配置文案，避免 `\uXXXX` 转义。
4. **`update_fields`**：Django 只生成这 4 列的 UPDATE，不会误改 `model_name`、`form_id`、`version` 等字段；这也是「保存设计」与「编辑元信息」分开的原因。
5. **身份来源**：`request.user_info.username` 由 `common/auth.py` 的 JWT 认证挂载，不是 Django 的 `request.user`。
6. **事务**：单条 UPDATE，数据库语句本身原子；这里不需要显式事务。

`ProcessGraph` 校验的实质（来自 `engine.py:63-115`）：

- `_check_xml_safe` 先拒绝空定义、含 `<!DOCTYPE` 或 `<!ENTITY` 的 XML，并限制单份定义不超过 2MB，避免 XXE 与实体膨胀；
- 用 `xml.etree.ElementTree.fromstring` 解析 XML，语法错误抛 `EngineError`；
- 遍历查找第一个本地名为 `process` 的元素，找不到说明不是合法 BPMN；
- 收集带 `id` 的 `userTask`、`exclusiveGateway`、`parallelGateway`、`startEvent`、`endEvent` 节点，以及带 `sourceRef/targetRef` 的 `sequenceFlow`；
- 把顺序流按 `source/target` 挂到节点的 `outgoing/incoming`，形成可推进的图索引；
- 若一个节点都没有，抛「BPMN 中未找到可执行节点」。

因此前端即使手工篡改 XML，保存阶段也会被拒绝并返回 `EngineError` 文案。注意：构造阶段不校验开始/结束节点数量，`start_node()` 在发起时才检查并抛「流程缺少开始节点」。

```python
def publish(self, request, pk=None):
    """发布模型：校验流程可解析，版本号 +1 并置为已发布。"""
    row = self.get_queryset().filter(id=pk).first()  # 模型（is_deleted=0）
    if not row:  # 不存在
        return fail('模型不存在', code=404)
    try:
        engine.ProcessGraph(row.bpmn_xml)  # 校验 BPMN：解析失败/结构缺失会抛 EngineError
    except engine.EngineError as exc:
        return fail(str(exc))
    if not row.form_id:  # 未绑定表单
        return fail('请先为流程绑定表单再发布')
    row.version = (row.version or 0) + 1  # 版本递增，实现版本隔离
    row.status = 1  # 已发布
    row.update_by = request.user_info.username  # 更新人
    row.update_time = time.strftime('%Y-%m-%d %H:%M:%S')  # 更新时间
    row.save(update_fields=['version', 'status', 'update_by', 'update_time'])  # 持久化
    return ok({'id': row.id, 'version': row.version}, '发布成功')
```

逐条说明：

1. **存在性**：`get_queryset()` 自动排除逻辑删除记录；已删除模型无法发布。
2. **XML 必须可运行**：发布时再次构造 `ProcessGraph`，与保存时的校验同源。即便有人绕过前端直接改库，也要过这一关。
3. **必须绑定表单**：`form_id` 为空时拒绝发布。发起页需要表单字段渲染与必填校验，因此发布前要完成表单绑定。
4. **版本语义**：`version` 从 0 开始，每次发布 +1；`WfInstance.model_version` 在发起时快照该值，实现「旧实例按旧版本运行、新实例按新版本运行」。
5. **状态语义**：`status` 由 0（草稿）改为 1（已发布）；停用是 2。`process_status`（0 运行中/1 完成/2 驳回/3 终止）是模型级统计字段，本方法不动它。
6. **事务**：只更新一行，天然原子；没有显式 `transaction.atomic()`。
7. **无重复发布保护**：已发布模型再次点发布，版本仍会继续 +1。前端列表按钮没有按 `status` 隐藏，这是现有行为。

```js
function validate() {
  const missing = fields.value.filter(field =>
    // 空值包括 null、空串、undefined 三种情况
    field.required && (formData[field.key] === null || formData[field.key] === '' || formData[field.key] === undefined))
  if (missing.length) {

    ElMessage.warning(`请填写必填项：${missing.map(item => item.label).join('、')}`)
```

```python
def start(self, request):
    """发起流程：校验表单必填项，创建实例并启动引擎。"""
    model_id = request.data.get('model_id')  # 模型 ID
    model = WfModel.objects.filter(id=model_id, is_deleted=0).first()  # 模型
    if not model:  # 不存在
        return fail('流程模型不存在')
    if model.status != 1:  # 未发布不可发起
        return fail('该流程尚未发布，无法发起')
    form_data = request.data.get('form_data') or {}  # 表单数据
    if isinstance(form_data, str):  # 兼容 JSON 字符串
        form_data = parse_json(form_data, {})
    form = WfForm.objects.filter(id=model.form_id).first() if model.form_id else None  # 绑定表单
    if form:  # 必填项服务端校验
        fields = parse_json(form.form_json, [])  # 字段数组
        missing = [f.get('label') or f.get('key') for f in fields
                   if f.get('required') and (
                       form_data.get(f.get('key')) is None
                       or str(form_data.get(f.get('key'))).strip() == '')]  # 缺失项
        if missing:  # 有必填未填
            return fail('请填写必填项：%s' % '、'.join(missing))
    now = time.strftime('%Y-%m-%d %H:%M:%S')  # 当前时间
    biz_key = request.data.get('biz_key') or '%s%s' % (
        (model.model_key or 'WF').upper(), time.strftime('%Y%m%d%H%M%S'))  # 业务单据号
    instance = WfInstance.objects.create(
        instance_key=uuid.uuid4().hex, model_id=model.id, model_version=model.version or 1,
        biz_key=biz_key, form_data=json.dumps(form_data, ensure_ascii=False),
        start_user_id=request.user_info.id, status=0, current_node=None,
        start_time=now, create_by=request.user_info.username, create_time=now,
        update_by=request.user_info.username, update_time=now, is_deleted=0)  # 创建实例
    engine_obj = engine.WorkflowEngine(instance, model)  # 构造引擎
    engine_obj.record(request.user_info.id, 'submit', '提交申请', None, None, '发起流程')  # 提交记录
    try:
        engine_obj.start()  # 启动并生成首个待办
    except engine.EngineError as exc:  # 流程定义问题
        WfAudit.objects.filter(instance_id=instance.id).delete()  # 清理提交记录
        WfTask.objects.filter(instance_id=instance.id).delete()  # 清理可能生成的待办
        instance.delete()  # 删除实例，避免留下孤儿数据
        return fail(str(exc))
    return ok({'id': instance.id, 'biz_key': biz_key}, '发起成功')
```

逐条说明：

1. **模型校验**：`is_deleted=0` + `status == 1`，只有已发布模型可发起；这是与示例 31/32 的衔接点。
2. **兼容字符串表单**：正常前端传对象；如果第三方系统传 JSON 字符串，用 `parse_json` 解析，避免 `form_data.get` 报 AttributeError。
3. **服务端必填校验**：字段定义来自 `wf_form.form_json`，逐项判断 `required` 且值是否为 `None` 或空白字符串；错误信息拼出中文 label。这层校验不能省，因为接口可被直接调用。
4. **业务单据号**：优先使用请求里的 `biz_key`；否则用「模型 Key 大写 + `yyyyMMddHHmmss`」。注意同一秒内同一模型发起两次，`biz_key` 会重复，但 `biz_key` 没有唯一约束，`instance_key` 才是唯一键（UUID hex）。
5. **创建实例**：`model_version=model.version or 1` 把发布版本快照进实例；`form_data` 以 JSON 文本存库；`status=0` 表示运行中。
6. **提交留痕**：`engine_obj.record(...)` 写一条 `action='submit'` 的 `wf_audit`，`task_id=None`，节点名写「发起流程」。
7. **启动引擎**：`engine_obj.start()` 从 startEvent 出发，遇到第一个 userTask 生成待办并暂停；如果 XML 缺少开始节点、网关成环等抛 `EngineError`。
8. **失败清理**：捕获 `EngineError` 后删除本次产生的 audit/task/instance，避免留下「有实例但没待办」的脏数据。这里是**手动补偿**，整个 `start` 方法没有包 `transaction.atomic()`（见文末疑似问题）。
9. **返回**：`{'id': instance.id, 'biz_key': biz_key}`，前端当前不消费，直接跳转「我的流程」。

```python
def _run(self, queue):
    """按顺序流队列推进 token，直到没有可推进的边。"""
    while queue:  # 队列非空
        self.steps += 1  # 累计步数
        if self.steps > MAX_STEPS:  # 防止死循环（MAX_STEPS=500）
            raise EngineError('流程流转步数超限，请检查网关连线是否成环')
        flow_id = queue.pop(0)  # 取一条顺序流
        flow = self.graph.flows.get(flow_id)  # 顺序流定义
        if not flow:  # 脏数据
            continue
        target = self.graph.nodes.get(flow['target'])  # 目标节点
        if not target:  # 目标节点缺失
            continue
        self._enter(target, flow, queue)  # 进入目标节点
    _save_state(self.instance, self.state)  # 推进结束后持久化状态
```

```python
def _create_tasks(self, node, flow):
    """为人工任务节点生成待办：解析审批人、审批方式、抄送与到期时间。"""
    pending = WfTask.objects.filter(instance_id=self.instance.id, task_key=node['id'],
                                    status=0, is_deleted=0)  # 节点已有待办则跳过
    if pending.exists():  # 防止循环/重复进入重复建任务
        return
    cfg = self.graph.cfg(node['id'], self.node_config)  # 节点配置
    assignees = self._resolve_assignees(cfg)  # 解析审批人
    if not assignees:  # 无审批人时兜底发起人，保证流程可继续
        assignees = [self.instance.start_user_id]
    assignees = self._dedupe(assignees)  # 去重保持顺序
    self._make_cc(node, cfg.get('ccUserIds') or [])  # 进入节点即抄送
    mode = cfg['approveMode']  # 审批方式
    if mode not in (1, 2, 3):  # 非法值回退或签
        mode = 2
    if mode == 1 and len(assignees) > 1:  # 串行：只建第一个人的任务
        self.state['serial'][node['id']] = assignees[1:]  # 其余排队
        assignees = assignees[:1]
    else:
        self.state['serial'].pop(node['id'], None)  # 非串行清空历史队列
    due_time = None  # 到期时间
    if cfg.get('dueHours'):  # 配置了超时小时数
        due_time = _now() + timedelta(hours=float(cfg['dueHours']))  # 计算截止时间
    now = _now()  # 统一时间
    for uid in assignees:  # 逐个生成待办
        WfTask.objects.create(
            instance_id=self.instance.id, task_key=node['id'], task_name=node['name'],
            assignee=uid, status=0, approve_mode=mode, due_time=due_time,
            start_time=now, create_by=self.instance.create_by or 'system',
            create_time=now, update_by=self.instance.create_by or 'system', update_time=now,
            is_deleted=0,
        )
    fire_listeners(self.model, 'enter', self.instance, node['name'])  # 节点进入事件
    self.state['waiting_node'] = node['id']  # 记录最近生成的节点
```

审批人解析（节选 `engine.py:379-417`，覆盖最常用的四种）：

```python
def _resolve_assignees(self, cfg):
    """按配置策略解析审批人用户 ID 列表。"""
    kind = cfg['assigneeType']  # 策略类型
    if kind == 'starter':  # 发起人本人
        return [self.instance.start_user_id]
    if kind == 'user':  # 指定用户
        return [int(x) for x in cfg['userIds'] if str(x).isdigit()]
    if kind == 'role':  # 指定角色下的启用用户
        role_ids = [int(x) for x in cfg['roleIds'] if str(x).isdigit()]
        if not role_ids:  # 未选角色
            return []
        from django.db import connection  # 局部导入，避免模块级依赖
        with connection.cursor() as cursor:  # 复用项目数据库连接
            placeholders = ','.join(['%s'] * len(role_ids))  # 参数占位
            cursor.execute(
                'SELECT ur.user_id FROM sys_user_role ur JOIN sys_user u ON u.id = ur.user_id '
                'AND u.is_deleted = 0 AND u.status = 0 WHERE ur.role_id IN (%s)' % placeholders,
                role_ids)
            return [row[0] for row in cursor.fetchall()]  # 返回用户 ID
    if kind == 'dept':  # 指定部门
        dept_ids = [int(x) for x in cfg['deptIds'] if str(x).isdigit()]
        if not dept_ids:  # 未选部门
            return []
        return list(SysUser.objects.filter(dept_id__in=dept_ids, status=0, is_deleted=0)
                    .values_list('id', flat=True))
    if kind == 'group':  # 指定用户分组
        if not cfg['groupId']:  # 未选分组
            return []
        ids = list(WfGroupUser.objects.filter(group_id=cfg['groupId']).values_list('user_id', flat=True))  # 分组用户
        return list(SysUser.objects.filter(id__in=ids, status=0, is_deleted=0)
                    .values_list('id', flat=True))  # 过滤有效账号
    if kind == 'expression':  # 动态表达式：结果按用户 ID 列表解析
        value = self._eval_assignee_expr(cfg.get('expr'))
        if isinstance(value, (list, tuple)):  # 列表形式
            return [int(x) for x in value if str(x).isdigit()]
        if str(value).isdigit():  # 单个 ID
            return [int(value)]
        return []
    return []  # 未知策略
```

```python
def _make_cc(self, node, user_ids):
    """生成抄送记录，同一实例同节点同用户只写一次。"""
    now = _now()  # 抄送时间
    for uid in self._dedupe([int(x) for x in user_ids if str(x).isdigit()]):  # 逐个抄送
        exists = WfCc.objects.filter(instance_id=self.instance.id, user_id=uid,
                                     node_id=node['id']).exists()  # 防重复
        if exists:  # 已抄送过
            continue
        WfCc.objects.create(instance_id=self.instance.id, user_id=uid, node_id=node['id'],
                            status=0, create_time=now)  # 写入抄送记录：status=0 未读

def sync(self):
    """同步实例状态：当前节点、是否完成、结束时间。"""
    pending = WfTask.objects.filter(instance_id=self.instance.id, status=0, is_deleted=0)  # 未完成待办
    node_ids = list(pending.values_list('task_key', flat=True))  # 当前节点 ID
    self.instance.current_node = ','.join(sorted(set(node_ids))) or self.instance.current_node  # 更新当前节点
    if not pending.exists() and self.instance.status == 0:  # 无待办且仍在运行
        self.instance.status = 1  # 置为已完成
        self.instance.end_time = _now()  # 记录结束时间
        fire_listeners(self.model, 'end', self.instance, '结束')  # 流程结束事件
    _save_state(self.instance, self.state)  # 持久化引擎状态
    self.instance.update_time = _now()  # 更新时间
    self.instance.save(update_fields=['current_node', 'status', 'end_time', 'engine_state', 'update_time'])  # 只写必要字段
```

发起后：

- 第一个节点是 userTask 时，`current_node` 被写成该节点 ID；
- 任务表新增一条或多条 `status=0` 的待办；
- 如果流程直接走到 endEvent（没有 userTask），`sync()` 发现无待办，实例状态立即变为 1（已完成）。

```python
    qs = self.get_queryset().filter(start_user_id=request.user_info.id)  # 只取本人发起
```

逐条说明：

1. **三重过滤**：`assignee=当前用户` + `status=0`（待办）+ `is_deleted=0`（未删除）。前端不需要也不能传 `assignee`，否则会越权查看他人待办。

3. **分页**：与「我的流程」共用 `StandardPagination`。
4. **没有复用 `_filters`**：`_filters` 是给全局任务列表 `list` 用的，支持 `status/assignee/instance_id`；我的待办必须锁死当前用户，所以单独写查询。
5. **任务状态含义**：0 待办、1 已办、2 已转派、3 已加签、4 已驳回；待办页只取 0。
6. **候选分组不参与过滤**：`candidate_group_id` 当前引擎生成任务时并没有写入（`_create_tasks` 只写 `assignee`），所以待办始终按具体用户过滤。

#### 视图业务逻辑

```python
def _task(self, request, pk):
    """取任务并校验归属人，防止越权处理他人待办。"""
    with transaction.atomic():  # 行锁事务，避免并发重复审批
        task = WfTask.objects.select_for_update().filter(id=pk, is_deleted=0).first()  # 锁定任务
        if not task:  # 不存在
            return None, fail('任务不存在', code=404)
        if task.assignee != request.user_info.id:  # 非本人任务
            perms = get_user_perms(request.user_info)  # 当前用户权限集合
            if '*:*:*' not in perms:  # 超管可代为处理/转派，其余用户越权
                return None, fail('只能处理分配给自己的任务', code=403)
        instance = WfInstance.objects.select_for_update().filter(id=task.instance_id).first()  # 锁定实例
        if not instance:  # 实例不存在
            return None, fail('流程实例不存在', code=404)
        if instance.status != 0:  # 实例已结束
            return None, fail('流程已结束，无法操作')
        model = WfModel.objects.filter(id=instance.model_id).first()  # 模型
        if not model:  # 模型已删除
            return None, fail('流程模型不存在')
        return (task, instance, model), None  # 三元组供动作复用

def approve(self, request, pk=None):
    """同意任务。"""
    with transaction.atomic():  # 审批写库与引擎流转同事务
        loaded, error = self._task(request, pk)  # 取任务
        if error:
            return error
        task, instance, model = loaded  # 解包
        comment = request.data.get('comment') or ''  # 审批意见
        engine.approve_task(instance, model, task, request.user_info.id, comment)  # 引擎推进
        return ok({'instance_status': instance.status}, '审批通过')
```

逐条说明：

1. **行锁**：`select_for_update()` 生成 `SELECT ... FOR UPDATE`，锁住任务行和实例行，防止两个人同时点同意导致重复推进。`_task()` 内部又开了一个 `transaction.atomic()`，在 Django 中嵌套 atomic 会变成保存点（savepoint），外层 `approve` 的 atomic 仍是真正提交边界。
2. **越权防护**：先判断 `task.assignee == 当前用户`；不相等时只有超管 `*:*:*` 可以代办，否则 403。
3. **实例状态**：只有 `status=0`（运行中）的实例允许审批；已完成/已驳回/已终止都拒绝。
4. **模型存在性**：实例所属模型被删除时无法构造引擎（拿不到 BPMN XML），直接报错。
5. **事务范围**：`approve_task` 内部会写 `wf_audit`、更新 `wf_task`、创建后续待办、更新 `wf_instance`，全部包在 `atomic()` 内，任一步异常整体回滚。
6. **返回**：`{'instance_status': instance.status}`，前端当前不用，只用成功提示。

#### 引擎内部：同意后如何推进

`approve_task()`（`engine.py:482-518`）：

```python
def approve_task(instance, model, task, operator_id, comment=''):
    """同意任务：按串行/或签/会签规则推进流程。"""
    engine = WorkflowEngine(instance, model)  # 构造引擎（重新解析 XML 与节点配置）
    engine.record(operator_id, 'approve', comment, task, task.task_key, task.task_name)  # 先记审批意见
    task.status = 1  # 当前任务已办
    task.end_time = _now()  # 完成时间
    task.update_by = str(operator_id)  # 更新人
    task.update_time = _now()  # 更新时间
    task.save(update_fields=['status', 'end_time', 'update_by', 'update_time'])
    mode = task.approve_mode  # 审批方式
    node_id = task.task_key  # 节点 ID
    if mode == 1:  # 串行：唤醒下一位
        remaining = engine.state['serial'].get(node_id) or []  # 排队人员
        if remaining:  # 还有人
            next_uid = remaining.pop(0)  # 取下一个
            engine.state['serial'][node_id] = remaining  # 回写队列
            cfg = engine.graph.cfg(node_id, engine.node_config)  # 取节点配置
            now = _now()  # 当前时间
            WfTask.objects.create(
                instance_id=instance.id, task_key=node_id,
                task_name=engine.graph.node(node_id)['name'], assignee=next_uid,
                status=0, approve_mode=1, due_time=task.due_time,
                start_time=now, create_by=instance.create_by or 'system', create_time=now,
                update_by=instance.create_by or 'system', update_time=now, is_deleted=0)  # 生成下一位待办
            engine.sync()  # 同步当前节点
            return
        engine.state['serial'].pop(node_id, None)  # 队列清空
    elif mode == 2:  # 或签：其他人待办直接关闭
        close_tasks(instance.id, node_id, operator_id, status=1)
    else:  # 会签：还有其他人未处理则等待
        others = WfTask.objects.filter(instance_id=instance.id, task_key=node_id,
                                       status=0, is_deleted=0)  # 其余待办
        if others.exists():  # 仍需等待
            engine.sync()  # 仅同步当前节点
            return
    engine.continue_from(node_id)  # 节点完成，继续流转
    fire_listeners(model, 'complete', instance, task.task_name)  # 节点完成事件
```

三种审批方式的实际效果：

| `approve_mode` | 同意后的动作 | 何时继续流转 |
| --- | --- | --- |
| 1 串行 | 从 `engine_state.serial[node_id]` 取下一人，新建一条待办 | 队列为空时 `continue_from` |
| 2 或签 | 当前人同意即代表节点通过，`close_tasks` 把同节点其他人待办置为已办 | 立即 `continue_from` |
| 3 会签 | 当前任务置已办，检查同节点是否还有 `status=0` 任务 | 只剩自己时 `continue_from`，否则等待 |

`close_tasks()`（`engine.py:473-479`）：

```python
def close_tasks(instance_id, node_id=None, operator_id=None, status=1):
    """关闭实例下（可限定节点）的待办任务。"""
    qs = WfTask.objects.filter(instance_id=instance_id, status=0, is_deleted=0)  # 未完成待办
    if node_id:  # 限定节点
        qs = qs.filter(task_key=node_id)
    qs.update(status=status, end_time=_now(), update_by=str(operator_id or ''),
              update_time=_now())  # 批量置为已办/驳回
```

```python
    with transaction.atomic():  # 保持事务一致性
        loaded, error = self._task(request, pk)  # 取任务（行锁 + 归属校验）
        if error:
            return error
        task, instance, model = loaded  # 解包
```

逐条说明：

1. **服务端强制意见**：`if not comment` 校验的是「空串/None」，不会 trim；前端已经 trim 过一次，正常流程不会带纯空格。接口被直接调用时，纯空格能绕过，这是一个轻微缺口。
2. **复用 `_task()`**：任务必须存在、属于当前用户（或超管）、实例仍在运行、模型存在。
3. **驳回是「整单终止」语义**：不是退回到上一个节点（退回是示例 39 的 `back`）。驳回后实例 `status=2`，所有待办关闭。
4. **事务**：留痕、关闭任务、更新实例全在 `atomic()` 内。
5. **无返回值消费**：`ok(None, '已驳回')`，前端只看成功提示。

#### 引擎内部：驳回如何终止

`reject_task()`（`engine.py:521-530`）：

```python
def reject_task(instance, model, task, operator_id, comment=''):
    """驳回任务：流程终止为已驳回，关闭全部待办。"""
    engine = WorkflowEngine(instance, model)  # 构造引擎（仅为复用 record 与监听器）
    engine.record(operator_id, 'reject', comment, task, task.task_key, task.task_name)  # 审批记录

    instance.save(update_fields=['status', 'end_time', 'update_time'])  # 持久化
    fire_listeners(model, 'reject', instance, task.task_name)  # 驳回事件
```

```python
def transfer(self, request, pk=None):
    """转审给其他用户。"""
    with transaction.atomic():  # 保持事务一致性
        loaded, error = self._task(request, pk)  # 取任务（行锁 + 归属 + 实例状态校验）
        if error:
            return error
        task, instance, model = loaded  # 解包
        target = request.data.get('user_id')  # 目标用户
        if not target:  # 未选择
            return fail('请选择转审人')
        if int(target) == request.user_info.id:  # 不能转给自己
            return fail('不能转审给自己')
        if not SysUser.objects.filter(id=target, status=0, is_deleted=0).exists():  # 目标无效
            return fail('转审人不存在或已停用')
        engine.transfer_task(instance, model, task, request.user_info.id, target,
                             request.data.get('comment') or '')  # 转审处理
        return ok(None, '转审成功')
```

逐条说明：

1. **目标人校验**：必须非空、不能是自己、必须是 `sys_user` 中 `status=0`（启用）且未删除的用户。
2. **归属校验**：`_task()` 要求 `task.assignee == request.user_info.id`；如果当前用户不是任务处理人，只有拥有 `*:*:*` 的超管才能代办转审。普通管理员即使有 `wf:task:transfer` 权限，也不能转派别人的任务（见文末疑似问题）。
3. **原任务处置**：引擎把原任务 `status=2`（已转派），不是删除，所以「我的已办」里能看到「已转派」记录。
4. **新任务**：同一实例、同一 `task_key`、同一 `task_name`，新 `assignee` 为目标用户，`approve_mode`/`priority`/`due_time` 沿用原任务。
5. **事务**：留痕 + 更新原任务 + 新建任务 + `sync()` 全在 `atomic()` 内。
6. **无返回值消费**：`ok(None, '转审成功')`。

#### 引擎内部：转审如何换人

`transfer_task()`（`engine.py:533-549`）：

```python
def transfer_task(instance, model, task, operator_id, target_id, comment=''):
    """转审：原任务置为已转派，为目标用户新建同节点待办。"""
    engine = WorkflowEngine(instance, model)  # 构造引擎
    engine.record(operator_id, 'transfer', comment, task, task.task_key, task.task_name)  # 审批记录
    task.status = 2  # 原任务已转派
    task.end_time = _now()  # 完成时间
    task.update_by = str(operator_id)  # 更新人
    task.update_time = _now()  # 更新时间
    task.save(update_fields=['status', 'end_time', 'update_by', 'update_time'])
    now = _now()  # 当前时间
    WfTask.objects.create(
        instance_id=instance.id, task_key=task.task_key, task_name=task.task_name,
        assignee=target_id, status=0, approve_mode=task.approve_mode, priority=task.priority,
        due_time=task.due_time, start_time=now, create_by=instance.create_by or 'system',
        create_time=now, update_by=instance.create_by or 'system', update_time=now,
```

```python
def back(self, request, pk=None):
    """退回上一步。"""
    with transaction.atomic():  # 保持事务一致性
        loaded, error = self._task(request, pk)  # 取任务
        if error:
            return error
        task, instance, model = loaded  # 解包
        try:
            engine.back_task(instance, model, task, request.user_info.id,
                             request.data.get('comment') or '')  # 回退处理
        except engine.EngineError as exc:  # 无可退回节点

        return ok(None, '已退回上一步')
```

逐条说明：

1. **`_task()` 前置校验**：任务存在、属于当前用户（或超管）、实例运行中、模型存在。
2. **`EngineError` 转业务错误**：找不到上游人工节点时返回 400，而不是 500。
3. **退回不要求意见**：与驳回不同，`comment` 可为空；页面也不强制。
4. **事务**：整个过程在 `atomic()` 内，任何数据库错误都会回滚。

#### 引擎内部：退回如何重建上游待办

`back_task()`（`engine.py:566-579`）：

```python
def back_task(instance, model, task, operator_id, comment=''):
    """退回上一步：关闭当前节点待办，在上一个人工节点重新生成任务。"""
    engine = WorkflowEngine(instance, model)  # 构造引擎
    previous = engine.graph.previous_user_task(task.task_key)  # 上游人工节点
    if not previous:  # 没有可退回节点
        raise EngineError('当前节点没有可退回的上一步')
    engine.record(operator_id, 'back', comment, task, task.task_key, task.task_name)  # 审批记录
    close_tasks(instance.id, task.task_key, operator_id, status=4)  # 关闭当前节点全部待办
    engine.state['serial'].pop(task.task_key, None)  # 清理串行队列
    engine.state['waiting_node'] = previous  # 记录回退节点
    engine._create_tasks(engine.graph.node(previous), {'id': ''})  # 在上游节点重建待办
    instance.status = 0  # 恢复运行中
    instance.end_time = None  # 清空结束时间
    engine.sync()  # 同步当前节点
```

`previous_user_task()`（`engine.py:136-154`）：

```python
def previous_user_task(self, node_id):
    """逆向查找最近的人工任务节点，供“退回上一步”使用。"""
    queue = list(self.node(node_id)['incoming'])  # 从当前节点的入边开始
    visited = set()  # 防止逆向成环
    while queue:  # 广度优先
        flow_id = queue.pop(0)  # 取一条入边
        if flow_id in visited:  # 已访问跳过
            continue
        visited.add(flow_id)
        flow = self.flows.get(flow_id)  # 顺序流
        if not flow:  # 脏数据跳过
            continue
        src = self.nodes.get(flow['source'])  # 源节点
        if not src:  # 节点缺失
            continue
        if src['type'] == USER_TASK:  # 找到上游人工节点
            return src['id']
        queue.extend(src['incoming'])  # 继续向上游搜索
    return None  # 上游没有人工节点
```

要点：

1. **「上一步」不是 XML 里直接相连的节点**，而是逆向 BFS 找到的最近一个 `userTask`；中间隔着排他/并行网关也会继续向上找。
2. **只关闭当前节点的待办**：`close_tasks(instance.id, task.task_key, ..., status=4)` 带 `node_id`，不会误伤其他并行分支的待办。
3. **在上游节点重建待办**：`_create_tasks(previous_node, ...)` 重新解析审批人配置，按原配置生成；如果上游节点此时仍有 `status=0` 的待办（并行分支未处理完），`_create_tasks` 因 `pending.exists()` 直接返回，不会重复建。
4. **串行队列清理**：清掉当前节点的 `serial` 排队，避免下次再进入该节点时沿用旧队列。
5. **实例状态恢复**：`status=0`、`end_time=None`；若实例之前是运行中，这里相当于无变化；`sync()` 会把 `current_node` 更新为上游节点。
6. **退回没有「步数」限制**：可以反复退回，只要上游存在人工节点。
7. **轨迹**：`record(action='back')` 写在关闭当前任务之前，所以审批记录保留当前节点名称。

```python
def trace(self, request, pk=None):
    """流程轨迹：审批记录 + 任务 + 当前节点。"""
    row = self.get_queryset().filter(id=pk).first()  # 实例
    if not row:  # 不存在
        return fail('流程实例不存在', code=404)
    audits = WfAudit.objects.filter(instance_id=row.id).order_by('id')  # 轨迹
    return ok({
        'instance': self._serialize(row),
        'audits': WfAuditSerializer(audits, many=True).data,
        'tasks': WfTaskSerializer(WfTask.objects.filter(instance_id=row.id, is_deleted=0), many=True).data,
    })
```

逐条说明：

1. **`audits` 按 `id` 升序**：`wf_audit.Meta.ordering = ['id']`，雪花 ID 随写入时间递增，因此时间线顺序等于操作顺序。轨迹里的节点名、操作人、意见、时间都来自这张表。
2. **`tasks` 含全部任务**：不只待办，还包括已完成（1）、已转派（2）、已加签（3）、已驳回（4），前端可展示每个节点的处理人。
3. **`canApprove`**：用 `tasks.filter(assignee=当前用户, status=0).exists()` 判断当前用户是否还有该实例的待办，决定详情里是否显示审批按钮；它不检查 `wf_task:approve` 权限，按钮是否可见仅由数据驱动。
4. **`model.bpmn_xml` 原样返回**：前端 bpmn-js 用它渲染流程图；`node_config` 解析为对象，前端用于读取节点配置。
5. **`form_data` 解析**：发起时存的是 JSON 字符串，这里转成对象，详情页可直接按字段 key 渲染。
6. **被删除模型**：`model` 为 `None`，详情仍返回实例、轨迹与任务，只是没有流程图；`_serialize(row)` 里的 `get_model_name` 会给 `'-'`。
7. **数据权限缺口**：`detail_info`/`trace` 的权限标识为空，任何登录用户只要知道实例 ID 就能查看任意流程的表单数据与审批意见。代码注释的意图是「发起人、审批人需查看」，但没有校验「当前用户是否是该实例的发起人/审批人/抄送人」（见文末疑似问题）。

```python
class WfCcViewSet(viewsets.ViewSet):
    """抄送：抄送我的列表与标记已读。"""
    permission_classes = [PermissionCheck]  # 统一权限校验

    @property  # 属性方法：抄送相关动作复用同一查询权限
    def perm_map(self):
        """接口动作到权限标识的映射。"""
        return {'mine': 'wf:cc:mine', 'read': 'wf:cc:mine'}

    def mine(self, request):
        """抄送我的列表。"""
        qs = WfCc.objects.filter(user_id=request.user_info.id).order_by('-id')  # 当前用户抄送
        return StandardPagination(request).paginate(qs, WfCcSerializer)

    def read(self, request, pk=None):
        """标记抄送为已读。"""
        row = WfCc.objects.filter(id=pk, user_id=request.user_info.id).first()  # 本人抄送
        if not row:  # 不存在
            return fail('抄送记录不存在', code=404)
        row.status = 1  # 已读
        row.save(update_fields=['status'])
        return ok(None, '已读')
```

逐条说明：

1. **数据权限**：`mine` 固定 `user_id=request.user_info.id`，不能通过参数查看别人的抄送。
2. **排序**：`-id` 最新抄送在前。
3. **分页**：复用 `StandardPagination`，结构 `{total,page,page_size,list}`。
4. **已读归属校验**：`read` 同时用 `id` 和 `user_id` 过滤，只有本人抄送才能标记；即使知道别人的 `wf_cc.id`，也返回 404。
5. **只更新 `status`**：`save(update_fields=['status'])` 只发一条 `UPDATE wf_cc SET status=1 WHERE id=...`，`WfCc` 没有 `update_by/update_time` 字段。
6. **幂等**：重复标记已读仍返回成功，只是再次写 `status=1`。

```python
    """生成抄送记录，同一实例同节点同用户只写一次。"""
    now = _now()  # 抄送时间
    for uid in self._dedupe([int(x) for x in user_ids if str(x).isdigit()]):  # 逐个抄送
        exists = WfCc.objects.filter(instance_id=self.instance.id, user_id=uid,
                                     node_id=node['id']).exists()  # 防重复
        if exists:  # 已抄送过
            continue
        WfCc.objects.create(instance_id=self.instance.id, user_id=uid, node_id=node['id'],
                            status=0, create_time=now)  # 写入抄送记录
```

```python
    instance_id = models.BigIntegerField('实例ID')  # 逻辑外键 → wf_instance.id
    user_id = models.BigIntegerField('抄送用户ID')  # 接收抄送的用户 → sys_user.id
    node_id = models.CharField('来源节点', max_length=64, blank=True, null=True)  # 抄送来源节点
    status = models.SmallIntegerField('状态', default=0)  # 0 未读 / 1 已读
    create_time = models.DateTimeField('创建时间', blank=True, null=True)  # 抄送时间

    class Meta:
        db_table = 'wf_cc'  # 物理表名
        managed = False  # 不参与迁移
        ordering = ['-id']  # 最新抄送在前
```

查询与更新 SQL：

```sql
-- 抄送我的
SELECT * FROM wf_cc
WHERE user_id = <当前用户ID>
ORDER BY id DESC
LIMIT <page_size> OFFSET <offset>;

-- 标记已读（归属校验体现在 WHERE 中）
UPDATE wf_cc SET status = 1 WHERE id = <cc_id> AND user_id = <当前用户ID>;
```

关联关系：`instance_id`、`user_id` 都是 `BigIntegerField` 逻辑外键，没有数据库约束。`WfCcSerializer`（`serializers.py:209-244`）逐行补充：

```python
model_name = serializers.SerializerMethodField()  # 模型名称
start_user_name = serializers.SerializerMethodField()  # 发起人
instance_status = serializers.SerializerMethodField()  # 实例状态
status_name = serializers.SerializerMethodField()  # 已读状态中文

def _instance(self, obj):
    """取抄送所属实例。"""
    return WfInstance.objects.filter(id=obj.instance_id).first()  # 单条查询

def get_model_name(self, obj):
    """模型名称。"""
    row = self._instance(obj)  # 实例
    if not row:  # 实例不存在
        return '-'  # 占位
    model = WfModel.objects.filter(id=row.model_id).first()  # 查模型
    return model.model_name if model else '-'  # 占位

def get_start_user_name(self, obj):
    """发起人名称。"""
    row = self._instance(obj)  # 实例
    return user_name(row.start_user_id) if row else ''  # 无实例返回空串

def get_status_name(self, obj):
    """抄送已读状态。"""
    return '已读' if obj.status == 1 else '未读'  # 二值状态
```

一行抄送最多触发 1 次实例查询 + 1 次模型查询 + 1 次用户查询，同样存在 N+1，但抄送列表通常数据量不大。

## 本模块小结

1. **两套 API 风格并存**：
   - 配置类资源（分类/表单/分组/模型/监听器/表达式）继承 `CrudViewSet`，通过 `perm_prefix` 自动生成 `wf:<资源>:list/create/update/delete` 权限，列表统一用 `filter_map + StandardPagination`。
   - 运行类资源（实例/任务/抄送）使用 `viewsets.ViewSet`，每个动作手写查询与权限映射，因为「我的」「待办」这类动作必须锁死当前登录用户。
2. **鉴权链路固定**：`request.js` 注入 `Authorization: Bearer <JWT>` → `common/auth.py` 的 `JWTAuthentication` 解析并挂载 `request.user_info` → `LoginRequired/PermissionCheck` 校验登录与 `perm_map` → 视图内再用 `request.user_info.id` 做数据权限过滤。
3. **统一响应**：所有接口返回 `{code,msg,data}`；分页 `data` 为 `{total,page,page_size,list}`；雪花 ID 由 `BigIntJSONRenderer` 转字符串，避免 JS 精度丢失。
4. **引擎无外部依赖**：`ProcessGraph` 自己解析 bpmn-js 的 XML，`WorkflowEngine` 用 `wf_instance.engine_state`（JSON）保存 arrivals/serial 等运行态；审批动作在 `views.py` 开 `transaction.atomic()`，引擎方法负责状态推进与留痕。
5. **版本隔离**：发布时 `wf_model.version+1`，发起时把版本快照写进 `wf_instance.model_version`；实例运行始终读取当前 `wf_model.bpmn_xml`，模型被删除则拒绝审批。
6. **逻辑外键**：全部关联字段是 `BigIntegerField`，没有数据库外键与级联；删除用户/分组/模型不会自动清理 `wf_task/wf_audit/wf_cc`，查询时需自行容错（序列化器大多返回 `-` 或空串）。
7. **事务边界不统一**：审批/驳回/转审/退回有 `atomic()`；发起流程、分组成员保存没有事务，依赖手动补偿或单条语句原子性。

### 疑似问题（仅记录，未修改任何代码）

1. **抄送页不自动加载**：`frontend/src/views/workflow/cc/index.vue` 引入了 `onMounted` 但全文未调用，首次进入列表为空，必须手动点查询。
2. **实例详情/轨迹存在横向越权风险**：`views.py:251` 把 `detail_info`、`trace` 的权限标识设为空串，任意登录用户知道实例 ID 即可查看表单数据与审批意见，未校验是否为发起人/审批人/抄送人。
3. **全局任务页转审权限不一致**：`task/index.vue` 对 `wf:task:transfer` 权限用户展示转派按钮，但 `_task()` 只允许任务归属人或 `*:*:*` 超管操作，普通管理员点击会收到 403。
4. **发起流程无事务且构造异常不在 try 内**：`WfInstanceViewSet.start` 先 INSERT 实例并写 audit，再 `WorkflowEngine(instance, model)`；构造函数会解析 BPMN，若 XML 非法抛 `EngineError`，此时异常发生在 `try` 之前，不会被清理逻辑捕获，会以 500 返回并留下实例/audit 脏数据。`start()` 阶段的异常才会走手动删除三张表的补偿。
5. **分组保存无事务**：`WfGroupViewSet.set_users` 先 `DELETE` 再逐条 `INSERT`，中途失败会出现成员被清空或只写入一部分。
6. **列表排序与模型声明不一致**：`WfCategory.Meta.ordering=['sort','id']`，但 `CrudViewSet.get_queryset()` 显式 `order_by('id')`，分类列表实际不按 `sort` 排序。
7. **复制模型 Key 存在冲突风险**：`WfModelViewSet.copy` 用 `model_key_copy_%H%M%S` 生成新 Key，同一秒内复制同一模型两次会触发唯一键冲突，且该方法未捕获 `IntegrityError`。
8. **驳回意见可用纯空格绕过**：后端 `if not comment` 不 trim，前端虽 trim 但接口可被直接调用。
9. **可发起流程未按用户权限过滤**：`WfModelViewSet.options` 只过滤 `status=1`，页面文案称「当前用户有权发起」，但后端没有按用户/角色/部门做发起权限判断。
