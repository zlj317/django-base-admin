### 2. 文件存储配置（重点）

`backend/config/settings.py` 中**没有显式配置 `MEDIA_ROOT` 和 `MEDIA_URL`**（Grep 只能找到 `BASE_DIR`、`STATIC_URL`）：

```python
BASE_DIR = Path(__file__).resolve().parent.parent   # backend/ 目录
STATIC_URL = 'static/'                              # 静态资源前缀
```

Django 全局默认 `MEDIA_ROOT = ''`，所以 `backend/apps/file/views.py:54`：

```python
upload_dir = os.path.join(settings.MEDIA_ROOT or 'media', 'uploads', month_dir)
# settings.MEDIA_ROOT 为空字符串，or 之后取相对路径 'media'
# 最终目录 = <启动进程当前工作目录>/media/uploads/YYYYMM
```

同理，下载与预览路径都用 `settings.MEDIA_ROOT or 'media'`（`backend/apps/file/views.py:105`、`199`）。这意味着：

- 文件实际落在**进程工作目录**下的 `media/uploads/YYYYMM/`，通常就是 `backend/media/...`；
- `backend/config/urls.py` 没有 `static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)`，Django 本身不提供 `/uploads/...` 或 `/media/...` 的静态访问；
- 前端 Vite 只代理 `/api`（`frontend/vite.config.js:17-22`），也没有 `/uploads` 或 `/media` 代理。

这三点会直接影响示例 66、68 的 URL 行为，后面会具体标注。

function apiUrl(action) {
  // 本模块统一前缀
  const base = '/task/info'
  // 按动作返回对应地址；未知动作返回 undefined，便于尽早暴露拼写错误
  return {
    list: base + '/list',        // GET 分页列表
    create: base + '/create',    // POST 新增任务
    update: base + '/update',    // PUT 更新，调用处拼 /{id}

// 拉取列表：try/finally 保证失败时也能复位加载态，错误提示由 request 拦截器统一处理
async function fetchList() {

  try {
    // GET 分页查询：query 内含分页与筛选条件

#### 视图业务逻辑

`backend/common/views.py:42-61`：

```python
def get_queryset(self):
    """返回过滤逻辑删除后的基础查询集，供各类操作复用。"""
    return self.model.objects.filter(is_deleted=0).order_by(self.order_by)
    # 只查未逻辑删除的任务，按 -id 排序

def apply_filters(self, queryset, request):
    """按 filter_map 把非空查询参数拼成 ORM 过滤条件。"""
    for param, lookup in self.filter_map.items():
        value = request.query_params.get(param)
        if value not in (None, ''):                      # 空值不当作筛选条件
            queryset = queryset.filter(**{f'{param}__{lookup}': value})
            # 例如 task_name__icontains=日报
    return queryset

def list(self, request):
    """列表接口：筛选 + 分页 + 序列化。"""
    queryset = self.apply_filters(self.get_queryset(), request)
    return StandardPagination(request).paginate(queryset, self.get_serializer_class())
    # 先 count 再 LIMIT，返回统一分页结构
```

- 权限：`list` 映射 `task:list`；`status`、`run_once` 没有映射，只校验登录。

// 立即执行：确认后手动触发一次，属于有副作用的写操作（会真实跑一遍任务）
async function handleRunNow(row) {
  await ElMessageBox.confirm(`确定立即执行任务「${row.task_name}」？`, '提示', { type: 'warning' })
  // POST /run_once/{id}：由后端立即投递一次执行，不改变原有调度计划
  await request.post(`/task/info/run_once/${row.id}`)
  // POST /api/task/info/run_once/{id}，无请求体
  // 只提示已触发，不刷新列表：任务是否成功需到“任务日志”页查看
  ElMessage.success('已触发立即执行')
}

```python
@action(detail=True, methods=['post'])
def run_once(self, request, pk=None):
    """手动触发一次任务：写一条 task_log 占位记录。"""
    task = TaskInfo.objects.filter(pk=pk, is_deleted=0).first()
    # 只允许操作未逻辑删除的任务
    if not task:
        return fail('任务不存在', code=404)          # 任务不存在返回业务码 404
    now = time.strftime('%Y-%m-%d %H:%M:%S')         # 统一时间格式
    TaskLog.objects.create(
        task_id=task.id,                             # 关联任务主键
        task_name=task.task_name,                    # 冗余任务名快照，改名后仍可追溯
        run_status=1,                                # 1 = 成功（演示实现直接标记成功）
        return_info='手动触发（演示：未实际调度）',     # 明确提示未真正执行
        cost_time=0,                                 # 耗时 0 毫秒
        run_time=now,                                # 开始运行时间
        create_time=now,                             # 入库时间
    )
    return ok(None, '任务已触发（演示：未实际调度）')  # data=None，只返回提示
```

#### 视图业务逻辑

- 校验：任务必须存在且 `is_deleted=0`。
- **没有真正调度**：不解析 `cron_expr/interval_sec`，不调用任何任务函数，不投递消息队列，只插入一条 `task_log`。
- **日志状态是 1（成功）**：没有执行却记为成功，`return_info` 里写了「演示：未实际调度」用于提示读者。这是演示实现的刻意行为，不应在生产使用。
- 权限：`run_once` 不在 `perm_map`，后端只校验登录；前端 `v-perm="'task:runOnce'"` 仅控制按钮显示。
- 审计：`TaskLog` 不继承 `BaseModel`，没有 `create_by/is_deleted` 等字段。

    module_name = '任务日志'

    def get_queryset(self):
        # TaskLog 没有 is_deleted 字段，不能复用基类的 is_deleted=0 过滤
        return self.model.objects.order_by(self.order_by)

    def list(self, request):
        """列表查询：TaskLog 不继承 BaseModel，直接过滤。"""
        queryset = TaskLog.objects.all().order_by('-id')  # 基础查询集，最新在前
        for param, lookup in self.filter_map.items():      # 逐参数读取
            value = request.query_params.get(param)        # 未传则跳过
            if value not in (None, ''):
                queryset = queryset.filter(**{f'{param}__{lookup}': value})
                # 动态拼 task_name__icontains / run_status__exact
        return StandardPagination(request).paginate(queryset, TaskLogSerializer)
```

#### 视图业务逻辑

- 为什么重写 `get_queryset()` 和 `list()`：基类默认 `filter(is_deleted=0)`，而 `TaskLog` 没有 `is_deleted` 列，直接调用会抛 `FieldError`。重写后只做筛选与分页。
- 权限：`list` 映射 `task:list`。
- 排序：固定 `-id`，无法按耗时/运行时间排序。
- 只读：前端没有新增/编辑/删除按钮，但后端仍继承了 `create/update/delete` 路由；由于 `TaskLog` 没有 `is_deleted`，基类 `delete()` 会走物理删除（`backend/common/views.py:119-123`）。

// 触发文件选择：点击隐藏的 input，浏览器会弹出系统文件选择框
function triggerUpload() { fileInputRef.value.click() }

// 文件选择后逐个上传：串行提交便于逐个给出成功/失败提示，也避免并发占用带宽
async function handleFileChange(e) {
  // FileList 转数组；取消选择时 files 为空
  const files = Array.from(e.target.files || [])
  if (!files.length) return                  // 用户取消选择，直接返回
  for (const f of files) {                   // 逐个文件串行处理
    // 每个文件单独一个 FormData，字段名 file 与后端接收参数对应
    const fd = new FormData()
    fd.append('file', f)                     // 后端 request.FILES.get('file')
    try {
      // multipart/form-data 由浏览器自动补 boundary，这里显式声明便于后端识别
      await request.post(apiUrl('upload'), fd, {
        headers: { 'Content-Type': 'multipart/form-data' }
      })
      // POST /api/file/upload，body 为 multipart/form-data
      ElMessage.success(`上传成功: ${f.name}`)
    } catch (err) {
      // 单个文件失败不影响后续文件继续上传；具体错误已由拦截器提示
      ElMessage.error(`上传失败: ${f.name}`)
    }
  }
  // 清空 input 的值，保证再次选择同一文件也能触发 change
  e.target.value = ''
  // 上传完成后刷新列表，展示新增附件
  fetchList()
}
```

```python
@action(detail=False, methods=['post'], parser_classes=[MultiPartParser, FormParser])
# parser_classes 指定用 multipart/form-data 解析器，把文件放进 request.FILES
def upload(self, request):
    """多文件上传：保存到 MEDIA_ROOT/uploads/YYYYMM/，按 MD5 去重。"""
    f = request.FILES.get('file')             # 取表单字段 file；未选文件时为 None
    if not f:
        return fail('请选择上传文件')           # 没有文件直接友好提示
    # 计算 MD5（分块读防止大文件撑爆内存）
    md5 = hashlib.md5()                       # 空哈希对象
    for chunk in f.chunks(8192):              # 每次读 8KB
        md5.update(chunk)                     # 逐块喂入
    file_md5 = md5.hexdigest()                # 32 位十六进制摘要，作为去重键
    # 秒传：已存在相同 MD5 则直接返回
    dup = WfFile.objects.filter(file_md5=file_md5, is_deleted=0).first()
    # 只在未删除记录里找，避免命中已删文件
    if dup:
        return ok({
            'id': dup.id,                     # 复用原记录 id
            'file_name': dup.file_name,       # 存储名
            'original_name': dup.original_name,
            'file_size': dup.file_size,
            'url': f"/uploads/{dup.storage_path.replace(os.sep, '/')}" if dup.storage_path else '',
            # 返回相对 URL；注意 storage_path 自身已以 uploads/ 开头
        }, '文件秒传')
    # 目录与随机文件名
    month_dir = time.strftime('%Y%m')          # 按年月分目录，避免单目录文件过多
    upload_dir = os.path.join(settings.MEDIA_ROOT or 'media', 'uploads', month_dir)
    # MEDIA_ROOT 未配置时退化为相对路径 media
    os.makedirs(upload_dir, exist_ok=True)     # 目录存在不报错
    ext = os.path.splitext(f.name)[1].lstrip('.')  # 取扩展名并去掉点
    random_name = f"{int(time.time()*1000)}_{os.getpid()}_{hash(f.name) & 0xffffff:06x}"
    # 时间戳 + 进程号 + 文件名哈希，降低重名概率
    if ext:
        random_name += f'.{ext}'               # 有扩展名才追加
    dest = os.path.join(upload_dir, random_name)          # 物理绝对路径
    storage_rel = os.path.join('uploads', month_dir, random_name)  # 相对 MEDIA_ROOT 的路径
    with open(dest, 'wb+') as out:             # 二进制写，with 保证异常时关闭
        for chunk in f.chunks(8192):           # 再次分块读取
            out.write(chunk)                   # 流式写盘
    user = getattr(request, 'user_info', None) # 当前登录用户
    now = time.strftime('%Y-%m-%d %H:%M:%S')   # 统一时间格式
    row = WfFile.objects.create(               # 落库文件元信息
        file_name=random_name,                 # 服务器存储名
        original_name=f.name,                  # 用户原始文件名
        file_ext=ext or '',                    # 无扩展名存空串
        mime_type=getattr(f, 'content_type', '') or '',  # 浏览器缺省时也存空串
        file_size=f.size or 0,                 # 大小 0 也存 0，避免 NULL
        file_md5=file_md5,                     # 去重键
        storage_type='local',                  # 当前实现固定本地存储
        storage_path=storage_rel,              # 入库相对路径
        upload_user_id=getattr(user, 'id', None),  # 上传者 id
        create_by=user.username if user else '',   # 审计字段
        create_time=now,
        update_by=user.username if user else '',
        update_time=now,
        is_deleted=0,                          # 初始未删除
    )
    return ok({
        'id': row.id,                          # 雪花 id（响应渲染时会转字符串）
        'file_name': row.file_name,
        'original_name': row.original_name,
        'file_size': row.file_size,
        'url': f"/uploads/{storage_rel.replace(os.sep, '/')}",  # 相对访问路径
    }, '上传成功')
```

#### 视图业务逻辑

- 入参：只认 `request.FILES['file']`，其他字段忽略。
- 去重：先算 MD5，命中未删除记录直接「秒传」，不重复落盘、不新增行。
- 落盘：`media/uploads/YYYYMM/<时间戳>_<进程号>_<哈希>.<ext>`；使用 `os.makedirs(..., exist_ok=True)` 保证目录幂等。
- 命名：`hash(f.name)` 是 Python 进程内的字符串哈希，**不同进程可能不同**（PYTHONHASHSEED 随机化），但只用于降低重名概率，不要求跨进程稳定。
- 入库：`WfFile` 继承 `BaseModel`，手工补 `create_by/create_time/update_by/update_time/is_deleted`。
- 权限：`upload` 不在 `perm_map`，后端只校验登录；前端 `file:upload` 只控制按钮显示。
- **没有校验**：文件大小上限、扩展名白名单、MIME 类型、私有文件归属都没检查；`wf_file_config` 里的上传配置也没有被读取。
- **URL 拼接疑似重复**：`storage_rel` 已经是 `uploads/YYYYMM/xxx`，再拼 `/uploads/` 会得到 `/uploads/uploads/YYYYMM/xxx`（见问题清单）。

  const base = '/file'
  return {

// 把字节数格式化为易读大小：B/KB/MB/GB，保留两位小数
function formatSize(bytes) {
  // 空值兜底（注意 0 字节是合法值，需单独保留），展示 '-' 而不是 '0 B'
  if (!bytes && bytes !== 0) return '-'
  if (bytes < 1024) return bytes + ' B'                            // 小于 1KB
  if (bytes < 1024 * 1024) return (bytes / 1024).toFixed(2) + ' KB'// 小于 1MB
  if (bytes < 1024 * 1024 * 1024) return (bytes / 1024 / 1024).toFixed(2) + ' MB'
  return (bytes / 1024 / 1024 / 1024).toFixed(2) + ' GB'            // 其余按 GB
}

// 拉取附件列表：query 同时包含分页参数与筛选条件，直接作为 URL 查询串提交
async function fetchList() {
  loading.value = true
  try {

```js
// 下载：以 blob 形式取回文件流，再用临时 a 标签触发浏览器保存
async function handleDownload(row) {
  // responseType=blob 让 axios 保留二进制（拦截器对 blob 直接透传原始响应）
  const resp = await request.get(`/file/download/${row.id}`, { responseType: 'blob' })
  // GET /api/file/download/{id}，响应类型为二进制
  // 生成临时对象 URL 指向内存中的 blob
  const url = window.URL.createObjectURL(new Blob([resp.data]))
  // 动态创建 a 标签模拟点击下载
  const a = document.createElement('a')
  a.href = url
  // 保存名优先原始文件名，其次存储名，最后使用通用名
  a.download = row.original_name || row.file_name || 'download'
  document.body.appendChild(a)
  a.click()
  // 下载触发后立即移除节点，避免污染 DOM
  a.remove()
  // 释放对象 URL，防止内存泄漏
  window.URL.revokeObjectURL(url)
}
```

```js
// 将 Blob 保存为文件
export function saveBlob(blob, filename) {
  // 为二进制内容创建一个可直接访问的临时 URL
  const url = window.URL.createObjectURL(blob)
  const link = document.createElement('a')
  link.href = url
  // download 属性告诉浏览器“下载而不是打开”，同时指定默认文件名
  link.download = filename
  // 部分浏览器要求链接必须在文档中才能触发点击，因此先挂到 body 再移除
  document.body.appendChild(link)
  link.click()
  document.body.removeChild(link)
  // 及时释放对象 URL，避免长时间占用内存（尤其大文件导出）
  window.URL.revokeObjectURL(url)
}
```

@action(detail=True, methods=['get'])
def download(self, request, pk=None):
    """下载文件：以原始文件名流式返回本地存储的文件。"""
    from django.http import FileResponse   # 延迟导入：仅下载动作需要
    row = WfFile.objects.filter(pk=pk, is_deleted=0).first()
    # 已删除文件不允许下载
    if not row:
        return fail('文件不存在', code=404)  # 记录不存在
    if not row.storage_path:                 # 没有存储路径说明文件未真正落盘
        return fail('文件未存储，无法下载')
    local_path = os.path.join(
        settings.MEDIA_ROOT or 'media',
        row.storage_path.replace('/', os.sep)
    )  # 库里存正斜杠，Windows 需要转成反斜杠
    if not os.path.isfile(local_path):       # 物理文件被外部删除时明确提示
        return fail('物理文件不存在', code=404)
    return FileResponse(
        open(local_path, 'rb'),              # 以二进制读方式打开文件句柄
        as_attachment=True,                  # 以附件形式返回，浏览器触发下载
        filename=row.original_name or row.file_name  # 优先原始文件名
    )
```

    model = WfFileRecycle                # 回收站快照模型（不继承 BaseModel）
    serializer_class = FileRecycleSerializer
    perm_prefix = 'file'                 # file:list/create/update/delete
    filter_map = {
        'file_name': 'icontains',        # 文件名模糊搜索
    }
    order_by = '-id'                     # 最新删除在前
    module_name = '文件回收站'

    def get_queryset(self):
        # 回收站记录不做逻辑删除过滤，直接按主键倒序返回全部快照
        return self.model.objects.order_by(self.order_by)

    @action(detail=True, methods=['post'])
    def restore(self, request, pk=None):
        """恢复回收站文件：把 wf_file.is_deleted 置回 0，删除回收站记录。"""
        recycle = WfFileRecycle.objects.filter(pk=pk).first()
        # 定位回收站快照；不存在说明已被彻底删除
        if not recycle:
            return fail('回收站记录不存在', code=404)
        user = getattr(request, 'user_info', None)   # 恢复操作人
        now = time.strftime('%Y-%m-%d %H:%M:%S')      # 统一时间格式
        affected = WfFile.objects.filter(pk=recycle.file_id).update(
            is_deleted=0,                            # 原文件置回未删除
            update_by=user.username if user else '', # 审计：更新人
            update_time=now                          # 审计：更新时间
        )
        if not affected:                             # update 返回受影响行数
            return fail('原文件已不存在，无法恢复')   # 原记录被物理清除时无法恢复
        recycle.delete()                             # 恢复成功后移除回收站快照
        return ok(None, '恢复成功')                   # data=None，只返回提示
```

#### 视图业务逻辑

- **删除时先写快照**：`backend/apps/file/views.py:82-94` 重写了 `delete()`，在基类逻辑删除之前，先为每个未删除文件写一条 `wf_file_recycle` 记录：

```python
def delete(self, request):
    """删除文件：先写回收站再逻辑删除，保证可从回收站恢复。"""
    ids = request.data.get('ids') or []        # 前端批量删除传 id 数组
    if not ids:
        return ok(None, '请选择要删除的数据')
    user = getattr(request, 'user_info', None)  # 删除操作人
    now = time.strftime('%Y-%m-%d %H:%M:%S')
    for f in WfFile.objects.filter(id__in=ids, is_deleted=0):
        # 只对未删除记录建回收站，避免重复快照
        WfFileRecycle.objects.create(
            file_id=f.id,                        # 关联原文件
            file_name=f.original_name or f.file_name,  # 优先记原始名
            delete_user_id=getattr(user, 'id', None),
            delete_time=now,
            create_time=now,
        )
    return super().delete(request)               # 交给基类做批量逻辑删除（is_deleted=1）
```

- **恢复**：
  - 按回收站 `pk` 找快照；找不到返回 404。
  - 按 `recycle.file_id` 更新 `wf_file.is_deleted=0`。
  - `affected=0` 说明原文件记录已被物理删除，无法恢复。
  - 恢复成功后删除回收站快照，避免同一条快照重复出现。
  - **没有检查物理文件是否存在**：如果磁盘文件已被手工删除，数据库恢复成功但下载仍会 404。
  - 权限：`restore` 不在 `perm_map`，只校验登录。
- **彻底删除**：`backend/apps/file/views.py:189-207`，先删物理文件，再删快照，最后物理删除 `wf_file` 行；异常被 `try/except` 吞掉，不影响删库。

#### Java 对照

| Django | Java/Spring 对应 |
| --- | --- |
| 删除前写快照 | Service 中先 `recycleRepository.save(...)` 再逻辑删除 |
| `restore` action | `@PostMapping("/restore/{id}")` |
| `filter(pk).update(is_deleted=0, ...)` | `@Modifying @Query("update WfFile f set f.isDeleted=0 ...")` |
| `recycle.delete()` | `recycleRepository.delete(entity)` 物理删除 |
| `affected` 受影响行数 | `int updated`，为 0 抛「原文件不存在」 |
| 前端循环批量恢复 | 对应后端未提供 `batchRestore`，由前端多次调用 |

## 08 模块小结

1. **任务调度（`apps/task_sched`）**
   - 路由挂 `/api/task/`，资源前缀 `info/log`。
   - `TaskInfo` 继承 `BaseModel`，有审计与逻辑删除；`TaskLog` 不继承，是纯日志表。
   - 列表、新增、编辑、删除复用 `CrudViewSet`；`run_once` 是自定义动作，当前仅写一条演示日志，**没有真正接入调度器**（仓库内没有 Celery/APScheduler 等调度组件）。
   - `task_log` 的 `run_status` 为 0/1/2，前端按 0 运行中、1 成功、2 失败显示。
2. **文件管理（`apps/file`）**
   - 路由挂 `/api/file/`，基础资源前缀为空，所以路径是 `/api/file/list`。
   - `WfFile`、`WfFileConfig` 继承 `BaseModel`；`WfFileRecycle` 不继承，回收站快照做物理删除。
   - 上传：MD5 秒传 + `media/uploads/YYYYMM/` 本地落盘 + `wf_file` 元信息入库。
   - 删除：先写 `wf_file_recycle` 快照，再逻辑删除 `wf_file`。
   - 下载：`FileResponse` 二进制流；预览：返回 kkFileView URL；Office：返回占位前端路由。
3. **共性**
   - 自定义动作（`run_once/upload/download/preview_url/restore/hard_delete`）都不在 `perm_map`，后端只校验登录。
   - 文件模块的配置表 `wf_file_config` 存在，但上传/预览代码没有读取它，配置页目前不产生实际效果。

## 疑似问题（仅记录，未修改代码）

1. **`MEDIA_ROOT` 未配置**：`backend/config/settings.py` 没有 `MEDIA_ROOT/MEDIA_URL`，`settings.MEDIA_ROOT or 'media'` 会退化成相对路径，文件位置取决于启动进程的工作目录；换启动目录后旧文件会“消失”。
2. **媒体文件没有路由**：`backend/config/urls.py` 没有 `static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)`；Vite 也只代理 `/api`（`frontend/vite.config.js:17-22`），上传返回的 `/uploads/...` 在开发环境无法直接访问。
3. **URL 重复 `uploads`**：`backend/apps/file/views.py:50`、`79`、`118` 都使用 `f"/uploads/{storage_path}"`，而 `storage_path` 自身已是 `uploads/YYYYMM/xxx`（`backend/apps/file/views.py:61`），最终得到 `/uploads/uploads/YYYYMM/xxx`。
4. **kkFileView 地址硬编码**：`backend/apps/file/views.py:117` 固定 `http://localhost:8012/onlinePreview`，未读取 `wf_file_config` 中的预览配置。
5. **下载错误被当成文件**：前端 `responseType='blob'`，后端 `fail()` 返回的是 JSON；文件不存在时会下载一个 JSON 文件而不是提示错误（`frontend/src/views/file/index.vue:239` + `backend/apps/file/views.py:102-107`）。
6. **回收站列表字段对不上**：前端展示 `original_name/file_size/storage_type/biz_type`（`frontend/src/views/file/recycle/index.vue:60-70`），但 `WfFileRecycle` 只有 `file_name/delete_user_id/delete_time/create_time`，这些列会显示空值。
7. **回收站搜索参数对不上**：前端传 `original_name`（`frontend/src/views/file/recycle/index.vue:113`），后端 `filter_map` 只认 `file_name`（`backend/apps/file/views.py:165`），按文件名搜索实际不生效。
8. **上传无限制**：`upload` 没有校验文件大小、扩展名、MIME、私有标记；`wf_file_config` 的上传限制配置未生效。另外方法 docstring 写「多文件上传」，但实现只读取一个 `file` 字段，多文件完全依赖前端循环调用（`frontend/src/views/file/index.vue:202-207`）。
9. **MD5 秒传跨用户复用**：`backend/apps/file/views.py:45` 只按 `file_md5` 查重，未限制上传人/业务归属；相同内容会把其他用户的文件元信息直接返回，私有文件也可能被复用。
10. **下载/预览/恢复越权**：`download/preview_url/restore/hard_delete` 都只校验登录，没有校验文件归属、`is_private`、`file:download`、`file:restore` 等权限；前端 `v-perm` 仅隐藏按钮。
11. **恢复不校验物理文件**：`restore` 只把 `wf_file.is_deleted` 置 0，不检查磁盘文件是否存在，恢复后下载可能仍 404。
12. **彻底删除的实例依赖**：`backend/apps/file/views.py:204-206` 先 `recycle.delete()`，随后仍读取 `recycle.file_id`。Django 内存实例的字段还在，所以当前能工作，但属于脆弱写法，建议先保存 `file_id` 再删。
13. **任务状态语义相反**：`backend/apps/task_sched/models.py:19` 注释 `0 正常 / 1 暂停`，前端 `frontend/src/views/task/info/index.vue:38-42`、`111` 按 `1 运行 / 0 暂停` 使用，保存后调度含义会反过来。
14. **立即执行写“成功”日志**：`backend/apps/task_sched/views.py:37` 在未真正执行时写 `run_status=1`，日志页会显示绿色「成功」，容易误导排障。
15. **任务日志重复路由**：`backend/apps/task_sched/urls.py:32-34` 在 `crud()` 已生成 `log/list` 后又重复声明 `'list'`，产生两条相同 path（功能不受影响，属于冗余）。
16. **前端无入口的接口**：`/file/office_url`、`/file/recycle/hard_delete` 的批量能力没有独立后端接口（批量靠前端循环）。
