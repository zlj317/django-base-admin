## 2. 为什么用单文件（而不是分表 CSV）

| 对比项 | 单文件 SQL（当前方案） | 分表 CSV（已弃用） |
|---|---|---|
| 还原 | 一条命令 `mysql < file.sql` 全量恢复 | 需按 93 个文件逐表导入，或额外写脚本 |
| 结构 | 建表语句与数据同文件，索引、注释、字符集不丢失 | 只有数据，结构仍需另存 SQL |
| 顺序 | 文件内已按业务依赖分组排序 | 需人工确定导入顺序 |
| 敏感字段 | 在生成时统一脱敏，文件头注明 | 每张表都要单独处理，易漏 |
| 可读性 | 表前有分组注释与行数标注，按表定位 | 93 个文件、无表间上下文 |
| 体积 | 约 315 KB（1300 行） | 93 个文件，体积相当但管理成本更高 |

## 6. 还原步骤

```bash
# 1. 建库（字符集与导出保持一致）
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS gen_admin DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci"

# 2. 导入结构与数据（单文件）
mysql -u root -p gen_admin < docs/数据库/django-base-admin-full-20261105.sql

# 3. 重置管理员密码（导出文件中 admin 密码为脱敏占位符）
cd backend
python manage.py init_db          # 重建基础表并重置 admin / 123456
```

> 注意：文件内每张表前均有 `DROP TABLE IF EXISTS`，**执行会清空同名表已有数据**，不要直接对生产库执行；生产升级仍以 `docs/*.sql` + `python manage.py init_db` 为准（见 [02-项目启动运行指南](../项目文档/02-项目启动运行指南.md)）。

如只需要重置密码、不想跑 `init_db`：

```bash
cd backend
python manage.py shell -c "from apps.system.models import SysUser; import bcrypt; \
u=SysUser.objects.get(username='admin'); u.password=bcrypt.hashpw(b'123456', bcrypt.gensalt(rounds=12)).decode(); u.save()"
```

## 9. 维护约定

- 本目录为**快照**，库结构或种子数据变化后需重新导出，避免与 `docs/*.sql` 建表脚本漂移。
- 重新导出时务必保持 `sys_user.password`、`bi_screen.share_password` 脱敏，且不要新增含口令的导出文件。
- 导出文件仅用于备份/交付/本地重建；生产发布仍以 `docs/*.sql` + `python manage.py init_db` 为准。
